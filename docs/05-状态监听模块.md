# 05 · 状态监听模块（State Watch Module）设计文档

> 模块定位：数据直读通道——不做视觉识别，直接读游戏写出的**日志与存档**获取状态。
> 状态：v0.3.0 已实现并实测通过（2026-10-13）。
> 关联：方案来自《04-数据直读方案》，本模块是其中的 P1 交付。

## 1. 背景与动机

原管线「截图 → 视觉模型 → 决策」单步 7~13 秒，延迟过高。侦查发现本游戏
（Probably Stolen Demo，Unity 2021.3.45f2 IL2CPP）自身会写出两类**明文数据**：

| 数据源 | 文件 | 更新频率 | 内容 |
|---|---|---|---|
| 运行日志 | `GameLog_*.txt`（每次启动新建） | 毫秒级（事件即时写入） | 顾客到达/意图/对话/交易/保存等事件流 |
| 存档 | `save_<槽位>.es3`（ES3 明文 JSON） | 2~4 分钟 + 关键节点 | 现金 / 租金 / 声望 / 11 个库存 / 经营统计 |

数据直读后：感知延迟从秒级降至**毫秒~百毫秒级**，信息量反而更大
（结构化字段，全部可回放、可离线测试，零模型成本）。

## 2. 模块范围

### 做

1. 定位游戏持久化目录（`%USERPROFILE%/AppData/LocalLow/<公司>/<产品>/`，可配置）；
2. 增量跟随最新 `GameLog_*.txt`（自动切换新会话文件、半行缓冲、截断防御）；
3. 解析日志行 → 结构化事件（顾客生命周期 / 交易 / 保存 / 价格……）；
4. 宽容解析 `save_*.es3`（修复三类非标 JSON 写法）→ 状态快照；
5. 「快照 + 事件流」组装为统一 `GameState`（含当前顾客推导、顾客会话重建）；
6. CLI `watch`（实时监听 / 单次采集 / 离线回放）与离线回放脚本。

### 不做（后续模块职责）

- 决策（brain 模块将改为消费本模块的结构化状态）；
- 控制（control 模块已有，事件驱动的触发逻辑属主循环改造，另行设计）；
- 任何形式的游戏内存注入（BepInEx 为备选升级项，尚未启用）。

## 3. 数据源细节（实测）

### 3.1 GameLog 日志

- 路径：持久化目录，文件名 `GameLog_YYYY-MM-DD_HH-MM-SS.txt`（每次启动新建）；
- 行格式：`[HH:MM:SS] [Log|Warning|Error] 消息`，含 Unity 富文本标记（解析时剥离）；
- 事件类型（`kind`）总表见 §5.1。

### 3.2 存档 save_*.es3

- 命名：`save_<槽位>.es3`；`SaveFile.es3`（设置）与 `saves_index.es3`（索引）不视为槽位；
- 结构：`{"playerStore": {..., "value": {...144 字段}}, "storeStation": {...}}`；
- 关键字段：`playerCash` / `runNumber` / `dayUntilRent` / `rentValue` / `storeReputations` /
  `storeClientManager` / `nightLogs` / `dialogHistory` / **11 个 `*InvJSON` 库存**（嵌套 JSON 字符串）/
  `storeStation.dayCounter|happiness|order|traffic`；
- **三类非标 JSON 写法**（宽容解析器修复，实测于全部 11 个真实存档）：
  1. 数字做键：`{8376:{...}}`（含**负数键** `-103:{...}`，窗口位置缓存字段）；
  2. 字符串内非法转义：中文全角引号被加反斜杠 `\“泥炭\”`；
  3. 嵌套层级：库存字段是「字符串形式的 JSON」，可分层修复（修复器可重入）。

## 4. 代码结构

| 文件 | 职责 |
|---|---|
| `game_agent/statewatch/lenient_json.py` | 宽容 JSON 解析：字符串感知状态机，修复数字键与非法转义 |
| `game_agent/statewatch/events.py` | 日志行 → `LogEvent`（精确匹配表 + 正则规则表） |
| `game_agent/statewatch/tailer.py` | 日志定位与增量跟随（文件切换 / 半行缓冲 / 截断防御） |
| `game_agent/statewatch/savefile.py` | 存档定位与解析 → `GameSnapshot`（含库存/声望提取） |
| `game_agent/statewatch/paths.py` | 持久化目录定位（配置 > 环境变量 > 自动推导） |
| `game_agent/statewatch/state.py` | 状态组装：`GameState` / `GameStateBuilder` / 顾客推导与流水重建 |
| `game_agent/statewatch/watcher.py` | `StateWatcher`：轮询监听（实时 `run` / 单次 `collect_once`） |
| `game_agent/cli.py` | `watch` 子命令（--once / --from-start / --json / --duration …） |
| `scripts/replay_session.py` | 离线回放：日志 + 配对存档 → 顾客流水报告 |
| `tests/test_statewatch.py` + `tests/fixtures/` | 34 项离线测试（含真实存档/日志样本） |

## 5. 输出契约（对下游的稳定接口）

### 5.1 LogEvent（日志事件）

```json
{"seq": 42, "ts": "09:19:12", "level": "Log", "kind": "client_intent",
 "message": "wanted2 SELL", "data": {"client_id": "wanted2", "intent": "sell"}}
```

| kind | 含义 | data |
|---|---|---|
| `client_approaching` / `client_arrived` / `client_leaving` / `client_left` | 顾客到店生命周期 | — |
| `client_intent` | 买卖意图 | `client_id` / `intent`(sell\|buy) |
| `client_dialogue` | 顾客开始对话（非买卖顾客，如 mentor 导师） | `client_id` |
| `conversation_ended` | 对话结束 | — |
| `action_started` / `action_ended` | 交易动作开始/结束 | — |
| `business_not_done` | 交易未成交（可靠信号） | — |
| `arrest_started` / `wanted_reported_correct` | 逮捕 / 正确举报通缉犯 | — |
| `game_saved` | 自动保存 | `slot` |
| `save_loaded` | 载入存档 | `slot` |
| `game_started` | 新局开始 | `profession` / `endless_mode` |
| `price_tracked` | 价格跟踪 | `price` |
| `other` | 其余消息（原文保留，不丢信息） | — |

### 5.2 GameSnapshot（存档快照）

核心字段：`slot` / `cash` / `run_number` / `day` / `day_until_rent` / `rent_value` /
`is_power_on` / `happiness` / `order` / `traffic` / `reputations[]` /
`inventories{name: [InventoryItem]}`（`name` 如 main / showcase / sold / back / trashcan…）。

### 5.3 GameState（统一状态，供 CLI / 未来 brain）

- `summary()`：精简摘要——现金 / 经营天数 / 当前顾客（推导）/ 库存件数 / 最近 10 条事件；
- `current_client()`：从事件流推导"当前在店顾客"（approaching → in_store → intent → conversation → leaving → left）；
- `rebuild_client_sessions(events)`：重建顾客会话流水（到达/类型/意图/结果/离开，
  结果 `outcome` 为启发式：not_done 可靠、completed 大概率、unknown 其余）。

## 6. 使用方式

### 6.1 CLI

```bash
python -m game_agent.cli watch --once                # 单次：当前快照 + 最近事件
python -m game_agent.cli watch                       # 实时监听（间隔 0.5s，Ctrl+C 停止）
python -m game_agent.cli watch --json                # 实时 NDJSON（供脚本/后续模块消费）
python -m game_agent.cli watch --once --from-start   # 回放：读取整个日志文件
python -m game_agent.cli watch --duration 60         # 监听 60 秒后自动退出
python -m game_agent.cli watch --data-dir <路径>      # 指定数据目录（默认自动推导）
```

### 6.2 离线回放脚本

```bash
python scripts/replay_session.py                       # 自动选最新会话
python scripts/replay_session.py --log GameLog_2026-10-08_09-16-34.txt
python scripts/replay_session.py --json                # JSON 输出
```

### 6.3 Python API

```python
from game_agent.statewatch import StateWatcher, resolve_data_dir

watcher = StateWatcher(resolve_data_dir())          # 实时模式
update = watcher.poll_once()                        # 增量（新事件 + 快照更新）
# 或：update = watcher.collect_once(from_start=True)   # 单次/回放

print(update.state.summary())
```

## 7. 实测验证（2026-10-13）

| 项目 | 结果 |
|---|---|
| 全部 11 个真实存档解析 | **11/11 成功**（最大 2MB / 367 件物品，单次解析 9~218ms） |
| 真实日志事件解析 | 84KB 日志 → 1812 条事件，含 65 位顾客完整生命周期 |
| 离线回放 | 10-08 会话重建 **49 位顾客流水**（28 种类型，卖 23 / 买 26），自动配对存档 save_15（现金 21005 / day 79 / 库存 236 件） |
| CLI 三种模式 | `--once` / 实时 `--duration` / `--from-start` 回放 全部通过 |
| 单元测试 | **34/34 通过**（全项目 90/90），含真实数据 fixtures 与人工构造的边界用例 |

## 8. 已知限制与风险

1. **快照新鲜度**：存档 2~4 分钟更新一次——现金等"静"数据可能略有滞后；
   事件流（毫秒级）负责"动"的部分，二者互补。未来可考虑高频轮询时用 mtime 判断。
2. **outcome 启发式**：顾客"是否成交"由日志信号推断（Business Not Done 最可靠），
   极少数情况可能误判（unknown 标记不猜测）。
3. **游戏版本兼容**：字段与事件名可能随游戏更新变化；解析器对缺失字段整体容错
   （返回 None 而非异常），事件表未命中时归入 other 保留原文。
4. **只读承诺**：本模块不写游戏文件（不改存档、不改日志），零封禁风险。
