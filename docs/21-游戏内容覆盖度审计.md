# 游戏内容覆盖度审计

> 2026-11-10。方法：先用外部资料列全「游戏有哪些内容」，再用项目代码/反编译源码列全「项目能操作什么」，
> 逐项对照。**结论先行：核心经营闭环能跑通，但"所有游戏内容"做不到——约 1/3 的系统缺数据或缺入口。**

## §3 项目接口现状

- **动作**：57 个（`ACTIONS`），另有 `force_dismiss` 仅供恢复不进模型参数表
- **端点**：`/state` `/machines` `/sellable` `/ui/objects` `/ui/nodes` `/ui/buttons(/all)` `/expedition` `/debug/{slots,client,machines}` `/decision` `/ping`
- **状态段**：30 段（含 v3.5 新增 difficulty/perks/mortgage/afterhour_events/locations/appraisal/aquaculture）
- **通用 UI 层**：`ui_hit` / `ui_click` / `object_action` / `ui_drag` —— 程序化派发指针事件，
  **不依赖物理鼠标**，因此在 `--no-mouse` 下仍可用。这是"没有专用动作"时的兜底路径。

## §5 结论

### 能完成的（核心闭环）

开门 → 接客 → 议价/成交 → 展示柜 → 打烊 → 夜间服务 → 房租 → 拾荒外出 → 电话/委托 → 存档，
以及射击、举报、雇工、远征。这条链路上的动作和状态都是齐的，且已在试玩版与正式版实机跑过主干。

### 不能完成的（按影响排序）

1. **真假货 / 商人验货**（❌ 最致命）：当铺的核心玩法是"看穿假货"，而 `itemFeatures` 没暴露，
   AI 只能按名字和价格瞎猜。**这是最大的能力缺口。**
2. **物品品相与特性**（❌ 通用）：水的杂质、食物新鲜度、枪械属性都挂在物品特性上，
   `item` JSON 只有 5 个字段，导致 8 条流派全部只能"投料看结果"，无法做质量决策。
3. **买店 / 扩建 / 买机器**（❌）：终局目标（把店买下来）没有动作入口，也没有首付/房价状态，
   只能靠 NPC 对话里 `dialog_choose` 撞。买机器与扩建同理。
4. **开箱 / 地下交易 / 以物易物 / 彩票 / 配给站换物**（❌）：五个"界面型"玩法无专用动作，
   只能 `ui_click` 兜底——能用，但依赖坐标与界面结构，稳定性远低于专用接口。
5. **犯罪值 / 幸运值 / 通缉名单 / 改造体**（❌）：四个数值/名单类系统完全不可见，
   影响"要不要卖违禁品、要不要举报、顾客是不是通缉犯"这类判断。
6. **机器模组安装**（❌）：模组只读不可装，机器性能提升路径走不通。

### 数字口径

- 内容项 40 项：✅ 15 项 / 🟡 14 项 / ❌ 10 项 / ➖ 3 项（其中 2 项为信息类）
- 换算：**真正能自主完成约 37%，需要 UI 兜底或数据不全约 35%，做不到约 25%**

## §6 建议的补齐顺序（按性价比）

| 优先 | 做什么 | 为什么 |
|---:|---|---|
| 1 | 物品 JSON 增加 `features[]`（`featureType`/`realCondition`/`fakeCondition`/`useCondition`） | 一个改动同时解锁"验货真伪 + 品相 + 水质 + 枪械属性"，覆盖最大缺口 |
| 2 | `mortgage` 段补 `store_price` / `down_payment` / `can_be_offered` | 终局目标第一次变得可规划 |
| 3 | 新增 `open_container` / `barter` / `buy_lottery` 三个动作 | 把三个高频 UI 玩法从"靠坐标"变成"靠接口" |
| 4 | `state` 补 `crime` / `luck` / `wanted` 三个数值 | 风险类决策的依据 |
| 5 | `machine_module_install` 动作 | 打通机器强化链 |

> 建议先做 1 和 2：改动小、影响面最大，且都能用反编译源码直接确认字段。

## §7 本轮顺带修正的知识卡

审计过程中发现 `mortgage-weekly-payment` 卡有实质错误并已订正：
正式版**没有固定首付 3000**（`LEGACY_DOWN_PAYMENT=3000` 在源码中只声明、从未被引用），
真实首付 = `max(500, round(房价 × 难度比例 / 500) × 500)`，
比例与期数为 cozy 0.2/8 周、normal 0.15/12 周、hard 0.125/16 周、challenge 0.2/16 周。

### 9.2 发现并修掉的问题（Python 侧，无需重启游戏）

1. **模型商 5xx 直接中断整步**：原逻辑只对 429 退避，503 立刻抛错，白掉一步。
   改为「5xx / `temporarily_unavailable` 同样退避」（5/10/15/20 秒，最多 4 次），
   与限流分开计数（`service_waits` vs `rate_limit_waits`）；401 仍然立即失败（不让错配 key 卡 50 秒）。新增 3 条测试。
2. **库存守卫文案误导**：正式版里顾客的货**要先开议价面板才摆出来**（实测 `not_owned` 0→3）。
   旧文案说"顾客物品里没有 X"，模型会以为自己记错货。改为：
   - 面板没开 → "先 open_negociation 让货摆上桌，此时 not_owned 为空是正常的"；
   - 面板已开 → 列出实际可收的物品名。
   同步改了 `next_step_hints`：顾客卖货但面板没开时，先提示开面板。新增 5 条测试。
3. 全量回归 **621 passed**。
