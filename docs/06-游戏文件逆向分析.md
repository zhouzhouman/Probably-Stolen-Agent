# 06 · 游戏文件逆向分析与底层操控方案

> 路线切换：从「截图 + 鼠标模拟」升级为「**逆向游戏文件 → 直接调用游戏内部逻辑**」（主流 AI 玩游戏方案）。
> 状态：逆向完成（2026-10-14）· BepInEx 6 已安装 · 待游戏重启验证注入。

## 1. 为什么这条路

- 鼠标模拟路线依赖窗口激活 + UI 坐标，脆弱（游戏失焦、UI 变化、动画时序都在干扰）；
- 游戏是 Unity **IL2CPP**，逻辑全部在 `GameAssembly.dll` 中，类/方法/字段结构可完整提取；
- 提取后可以**直接调用游戏方法**（开门、叫号、接受报价……）并**直接读内存数据**
  （顾客预算、价格修正、交易对象——比存档和截图都更实时更丰富）；
- 这正是 Minecraft Mineflayer、各类游戏 bot 的主流思路：**绕过 UI，直控逻辑**。

## 3. 核心类地图（游戏逻辑全貌）

| 类 | 职责 | 关键点 |
|---|---|---|

| `StoreShutterButton` | 卷帘门按钮（单例） | `OpenShutter` / `CloseShutter` / `ToggleShutterDoor` |
| `DialogUIManager` | 对话系统（单例） | `ContinueConversation` / `IsChoice` / `SelectChoice` |
| `NegociationUIManager` | 议价/成交系统（单例） | `OnOfferAcceptClick` / `BuyItem` / `SellItem` / `SellMultiple` |
| `StoreClientList` | 顾客列表管理 | 队列、未来顾客排队 |

## 4. 关键操控 API（全部为 public，插件可直接调用）

### 4.1 店铺营业（用户点名需求）

| 操作 | API |
|---|---|
| **开门（卷帘门）** | `PlayerStore.Instance.OpenShutter()` 或 `StoreShutterButton.Instance.OpenShutter()` |
| **关门** | `StoreShutterButton.Instance.CloseShutter()` / `EndAndClose()`（打烊） |
| 切换门状态 | `StoreShutterButton.Instance.ToggleShutterDoor()` |
| **呼叫下一位顾客** | `PlayerStore.Instance.TryCallNextClient()` |
| 能否叫号 | `CanNextClient()` / `IsClientPresent()` / `IsClientDimissable()` |
| 打发当前顾客 | `DismissCurrentClient(callNextWhenPossible: true, right: true, interruptDialog: true)` |
| 预排队顾客 | `QueueFuturClient(id, day)` / `HandleFutureClientQueue()` |

### 4.2 对话与交易

| 操作 | API |
|---|---|
| 开始顾客对话 | `StoreClient.StartMainDialogue()` |
| **推进对话** | `DialogUIManager.Instance.ContinueConversation()` |
| 对话选项 | `IsChoice()` / `SelectChoice(index)` |
| 对话状态 | `IsCurrentDialogEnd()` |
| **接受报价** | `NegociationUIManager.Instance.OnOfferAcceptClick()` |
| 按物品成交 | `NegociationUIManager.Instance.BuyItem()` / `SellItem()` / `TrySellItem()` / `SellMultiple(items)` |
| 批发 | `OnWholesaleClick()` |
| 从柜台买入/卖出 | `PlayerStore.Instance.BuyItemFromTable()` / `SellItemFromTable()` |
| 交易完成 | `StoreClient.CompleteBusiness()` |

### 4.3 经济与日循环

| 操作 | API |
|---|---|
| 现金 | `PlayerStore.Instance.GetCash()` / `CanPay(price)` / `PayMoney(amount)` |
| 开始一天 | `BeginDay()` / `CanStartDay()` |
| 结束一天 | `EndDay()` / `CanEndDay()` / `EndNight()` |
| 存档 | `SaveGame()`（public）· `LoadGame()` |
| 租金 | `GetRentValue()` / `CanPayRent()` / `OnRentPaid()` |

## 5. 数据模型（AI 决策信息源，内存实时读取）

### StoreClient（当前顾客，字段全公开）

```
displayName / identifier      顾客身份
clientCash / clientBudget     顾客的钱与预算（可推断砍价空间）
buyPriceModifier/sellPriceModifier  价格修正系数
clientBuyingTagList/IdList    想买的东西（标签/ID）
clientBlackTagList/IdList     拒收的东西
dismissable / arrestable      可否打发 / 可否逮捕
isBusinessComplete            本单是否完成
barterOffer                   议价对象
serviceCost                   服务费
isOfferWholesale / wholesaleDiscount  批发出价与折扣
```

### 状态读取入口

- `PlayerStore.Instance`（含 `playerCash` 等公开字段）
- 当前顾客：`PlayerStore.Instance` / `StoreClientList` 中获取
- 成交数据：`NegociationData` / `BarterOffer`（当前报价）

## 8. 风险与注意事项

1. **线程模型**：Unity API 必须在主线程调用——插件内所有游戏调用通过主线程队列派发；
2. **调用等价性**：直接调方法与点击 UI 的副作用基本一致，但个别流程含协程/动画
   （如开门有动画），调用后需按效果轮询确认（读状态）而非假定立即完成；
3. **试玩版差异**：部分方法可能有 Limited build 检查（如 `IsStartTypeInLimitedBuild`）；
4. **不写存档**：V1 只读状态 + 调方法，不直接改存档文件；
5. **可逆性**：删除 BepInEx 文件即恢复原游戏；插件本体只读+调 API，不做破坏性修改。
