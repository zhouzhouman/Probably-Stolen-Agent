## 0. 一句话结论

**这是一个"守卫体系极扎实、工程治理明显滞后"的项目，而最大的风险不在代码，在时间线。**

三件事必须在 2026-12-10 之前处理，否则整个桥接会在游戏侧被拒绝加载，后面所有机制优化都失去载体：

1. `mod/manifest.xml:38-47` 声明了 **`reflection-external`**——官方 modding 文档 `APIChanges.md` 已把它列为**已废弃能力，2026-12-10 起硬拒绝**；而项目实际反射的都是 `Assembly-CSharp.dll` 内的游戏类型，按官方规则**属于免费反射，根本不需要这个能力**。
2. `mod/manifest.xml:15` 的 `GameVersions=0.46D` 是**发售前遗留、长期未递增的旧版本字符串**；官方 100-Rev14 起改为点分版本 `1.0.0.14`，前缀匹配 `1.0.0`。
3. `mod/src/BridgeServer.cs` 用 `ThreadPool` + `AcceptLoop` 自建线程，而 `threads` 同属 12-10 起硬拒绝的废弃能力；需迁到 `ModHelper.RunInBackground` / `RunOnMainThread`。

> 来源：https://github.com/dragonpan2/probably-stolen-modding/blob/main/APIChanges.md 、`ModdingGuide.md`（开发者在 Steam 讨论帖亲自给出的仓库）。详见 `docs/25` §0。

排在这之后的 P0 是**工程治理**：37 个回归测试因同名类覆盖永不执行、五套版本号漂移、动作白名单 5+ 处手工维护、状态签名硬编码下标。修这四项的收益远大于继续堆守卫。

### 1.2 模块依赖方向

```
cli.py ──> agent_loop.py ──┬─> brain.{brain,prompt,schema,client}

                          ├─> knowledge (mechanic_block)
```

`game_agent/agent_loop.py`（1930 行）是事实上的上帝模块：导入 10 个内部包，编排从感知到落盘的全链路。`step_once()`（`:1273-1617`，344 行 / 21 个参数）把观察、知识、目标、守卫、恢复、收纳、浮层、落盘全塞在一个函数里，任何守卫调整都要在这里动刀。

三个感知通道（`bridge` / `statewatch` / `vision`）互不依赖，由 `structured/channels.py:pick_source()` 统一选择——这个设计是好的，应保留。

## 4. 三个会改变改造方向的裁决（联网核查后）

> 这三条纠正了本地旧文档与部分代码注释，写进 `docs/26` 的任务卡时以本节为准。

### 裁决 A：远征 / 雇工在正式版 1.0 **未实装**，应冻结而非补齐

- 官方 2026-10-21 的 1.0 预告把 `Expedition` 明确列在 **post-launch updates**；官方 11-06 Roadmap 说 11 月只做 bug 修复 / QoL，内容更新排 **12 月中旬（Junker + 远征）、1 月、4 月**。中文维基 `hiring-crew` / `expedition-locations` 页已删除。
- 来源：https://store.steampowered.com/news/app/4348910/view/689770861148766944 、https://store.steampowered.com/news/app/4348910/view/676262708841021730 、https://games.gg/news/probably-stolen-cyberpunk-shopkeeper-sim-next-update-roadmap
- **因此**：`docs/12:218` 与 `docs/21` 把「远征/雇工」列为待补动作缺口是**过时结论**；本项目的 `expedition_send`/`hire_worker` 恒拒在当前版本是正确行为。正确做法是：从模型可见白名单移除（避免浪费决策步数）、错误文案改为「本版本未实装」、保留只读 `/expedition` 与 `unlocked` 作为**版本探测开关**，等官方上线再解锁。`knowledge/mechanics/quest/` 内远征相关卡标 `gated_until`。

### 裁决 B：没有官方维基；本地 `wiki_raw` 是 Demo 期快照

- 多个粉丝站书面否认官方 wiki 存在；`wiki.gg` 返回 Cloudflare 挑战页，Fandom 未找到。实际可用来源按可信度排序见 `docs/25` §0.1。
- `knowledge/wiki_raw/_SPEC.md` 抓取于 **2026-10-24**，即正式版发售（10-28）前 4 天，源站 `probably-stolen.nicokobo.com/zh/wiki/terms/*` 多数现已失效。其 203 张卡中 158 张被 `artifacts/knowledge_review.md` 判为高风险。
- **因此**：机制数值一律以「官方 modding 文档 / Steam 官方公告 → BWIKI 正式版解包 → nicokobo 聚合页 → Ludens 实测 → 英文粉丝站」取数，Demo 快照只作对比，不得写进新接口实现或提示词。已证实的冲突见 `docs/25` §0.3。

### 裁决 C：`TreeNode` 不是技能树

- 联网核实：游戏内「节点（小）/（中）」是**机器模组舱内的辅助加成物品**（按相邻模组基础属性的 1/5 提供加成）；项目 `mod/src/BridgeApi.cs:4192` 的 `TreeNodeRender` 是**自绘 UI 的可拖拽渲染节点**（`IBeginDragHandler`）。
- 真正的「升级解锁树」是 **Wilds 网络的前置依赖链**（购买项目 → 介绍 → 入队/启用），入口是电话 `8376`。
- **因此**：不要把 `/ui/nodes` 当成技能树数据；`ui_drag` 定位的是 UI 矩形。二者在设计文档中必须分开命名。
- 来源：https://probably-stolen.nicokobo.com/zh/collections/machines-and-modules 、https://probably-stolen.nicokobo.com/zh/tools/modules 、https://probably-stolen.nicokobo.com/zh/collections/wilds-network
