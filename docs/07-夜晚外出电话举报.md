## 1. 游戏完整日循环（调研结论）

```
早晨 begin_day →（MORNING：报纸/日历/晨报）→ open_shutter 开门
  → call_next 接待顾客（买卖/估价/委托/房东收租）
  → 顾客队列空 → end_day 打烊
  →【夜晚服务面板 EndOfDayUIManager】勾选服务 → 确认扣费
  →【夜间地图 MapUIManager】选去向：
       ├─ go_out commissary 配给站（信用点兑换/购物，内部有黑商 Bazar）
       ├─ go_out upgrade     升级商人（买店铺升级）
       ├─ go_out scavenging  拾荒（冒险淘货，可能受伤）
       └─ stay_home          睡觉（不出门）
  → 外出地点办事 → leave_outside 返回
  → 次日 begin_day
```

关键事实（网络攻略 + 代码交叉验证）：

| 机制 | 结论 |
|---|---|
| 夜晚服务 | 打烊后一次选购机会，共 9 项服务（见 §2），确认后当晚扣费生效 |
| 外出机会 | 每晚一次（`PlayerStore.visitLeftTonight`），重伤（`HealthData.IsSeriouslyWounded`）或次数用完只能睡觉 |
| 拾荒 | 每晚数次机会（`scavengingAttempts` 计数），随机获得材料/商品/背包，有轻/重伤风险；受伤后可用绷带继续，伤口恶化会阻断外出 |
| 配给站 | 用 Tokens（信用点，独立货币）兑换 ration；内部有黑商（什么都能收但 -15%） |
| 升级商人 | 购买店铺升级（展示柜扩建/买家推荐/翻新等） |
| 电话 | 店内有电话机，拨号盘 + 通讯录；6 个联系人（见 §4） |
| 举报 | 店内侧栏「治安部」长按按钮（StoreSecButton），仅通缉犯/伪人等可逮捕顾客可举报；成功拿悬赏+治安部声望，掉被举报者派系声望；错报有惩罚（wrongfulReportCount/wrongfulReportMax） |
| 伪人 | 改造体（aug），全阵营共识「发现立即击毙」；正确打法：正常交易赚一笔 → 射击击毙 → 举报拿悬赏 |
| 报纸/日历 | 次日物价信息可在开店前从日历看到（AdvCalendarUIManager.nightlyReportButton 夜间报告） |

## 2. 夜晚服务（EndOfDayUIManager + StoreService）

`PlayerStore.storeService`（List<StoreService>），存档实测 9 项：

| id | 中文名 | 费用 | 说明 |
|---|---|---|---|
| POWER_SERVICE | 电力服务 | 5 | 给机器供电（有电器再开） |
| INSURANCE_SERVICE | 保险服务 | 4 | 防夜间失窃（不买可能被偷） |
| JANITORIAL_SERVICE | 清洁服务 | 3 | 防垃圾降吸引力 |
| SEC_INFORMANT | 盘查预警 | 10 | 检查预警（ HandleInspectionEarlyWarning ） |
| BUY_REFERAL | 买家推荐 | 10 | 拉买家 |
| SELL_REFERAL | 卖家推荐 | 10 | 拉卖家 |
| CRIMINEL_NETWORK | 违禁品买家推荐 | 45 | 高利润违禁品买家，3 天冷却 |
| WILD_FIXER | 王尔德的善后人 | 25 | 清除证据（犯罪点高时买） |
| CARTEL_PROTECTION | 卡特尔保护费 | 0 | **强制**（mandatory） |

StoreService 字段：`id / displayName / cost / unlocked / introduced / isUsing /
totalCooldown / currentCooldown / isMandatory / tooltip`。
`isUsing` = 今晚已选中（界面 Toggle 即写此字段），`end_day_confirm` 确认后统一扣费
（PlayerStore.HandleOtherServices / HandleJanitorial / HandlePower / HandleInsurance /
HandleInspectionEarlyWarning 在 FireOnHandlingNightlyServicesEarly/Late 时处理）。

## 3. 夜间地图（MapUIManager）

- 目的地枚举 `MapLocation`：COMMISSARY=0 / UPGRADE_MERCHANT=1 / SCAVENGING=2 / STORE=3
- 流程：`OpenUI()` 打开地图 → 点目的地（设 currentLocation）→
  `OpenGoOutsideConfirm()` 弹「外出确认」→ `OnGoOutsideConfirm()` 确认出发
- `Sleep()` = 不出门睡觉；`ScavengeButtonClick()` = 开始一次拾荒；
  `HandleLeaveCommissary/HandleLeaveUpgradeMerchant/HandleLeaveScavenging` = 从各地返回
- 状态观测：`isOutside` / `currentLocation` / `mapPanel.activeSelf` /
  `PlayerStore.visitLeftTonight` / `scavengingAttempts` /
  `healthData.woundState|isWoundStable|isWoundedFresh` / `HealthData.IsSeriouslyWounded()`

## 5. 举报与射击（StoreSecButton / StoreUIManager）

- `StoreSecButton`：店内侧栏**长按**按钮（IHoldClickable），灯亮（lit sprite）表示
  当前顾客可逮捕；`IsClientArrestable()` 判定；`OnClick()` 执行举报
- `StoreClient` 相关字段：`isWanted / isStealthWanted / reportReward（悬赏）/
  reputationPenalty（举报声望代价）/ arrestable / isAug / realName / reported / CanReport()`
- `PlayerStore.OnCustomerReported()` 结算；`StoreReputation.ReportedClient(factionId)` 记录；
  错报计数 `PlayerStore.wrongfulReportCount / wrongfulReportMax`
- 射击：`StoreUIManager.EnterShootingMode() / Shoot() / CanShoot() / ExitShootingMode()`，
  目标为当前顾客（`shotClientInstance`）；处决动画后有举报后续

## 7b. 真机验证结果（2026-10-14 22:40 实测，v0.8.0）

AI 用真实 brain（GLM-5.3-Flash）+ bridge 通道 live 跑了 36 步，验证结论：

| 项目 | 结果 |
|---|---|
| 夜晚流程全链路 | ✅ **完整跑通**：end_day → night_services → end_day_confirm → stay_home → begin_day → open_shutter |
| 夜晚服务扣费 | ✅ **真实生效**：confirm 后现金 593→588（=POWER_SERVICE 费用 5） |
| report_client | ✅ 两次均成功：一次香烟贩子（游戏按钮点亮、CanReport=true，合法举报）、一次通缉犯 wanted3（悬赏 100） |
| 交易循环 | ✅ 收购/卖出/送客/换客自主决策正常（现金 550→593，含 4 次卖出 +3 次收购） |
| **空号浪费（实盘发现）** | ❌ 发现：队列空了 AI 仍 call_next→wait→call_next→wait→call_next 试探 3 次才打烊 |

### v0.8.1 修复（2026-10-14 22:50）：顾客队列权威信号

- `/state` 新增 `queue` 段：`{can_next: CanNextClient(), has_client: IsClientPresent(), count: clientStack.Count}`
- `call_next` 加守卫：`can_next=false` 且无顾客 → 直接拒绝并指引进入夜晚流程；
  并按 store_state 区分「门未开（先 open_shutter）」「新一天未开始（先 begin_day）」「队列已空（打烊）」三种情况
- observer：队列空且无顾客时 available_actions 出「打烊进入夜晚流程」而非「呼叫下一位顾客」，
  visible_info 增 queue 段，important_objects 增「顾客队列」对象
- prompt 规则 5 重写：以 `queue.can_next` 为权威信号，**严禁试探性叫号**
- state_signature 15 → 16 字段（+can_next，队列空的转换可唤醒事件驱动循环）
- 测试 250/250 通过；DLL v0.8.1 已部署

## 8. 借鉴的开源 AI 玩游戏项目（网络调研）

- **lmgame-org/GamingAgent**（ICLR 2026）：LLM/VLM 游戏 agent 基准 + harness，
  Gymnasium 标准化接口（Sokoban/Tetris/2048/Pokemon Red…），CUA 部署方案。
  借鉴点：游戏环境接口标准化思路（本项目的 /state + ACTIONS 白名单即轻量版）。
- **NokkTsang/AI_Gaming_Agent**：通用计算机控制 agent（参考 Cradle 架构），
  Game-TARS 特性：双层记忆（2480 步）、稀疏思考（简单动作跳过推理加速 3-4 倍）、
  卡死检测自动恢复、反应式规划（2-5s vs 45s）。借鉴点：卡死检测与恢复策略可融入
  agent_loop 的熔断机制；稀疏思考可降低主循环 API 成本。
- **donghaozhang/GamingAgent**：OpenRouter 统一 API + 多游戏自动播放。
  借鉴点：auto-play 模式与延迟配置经验。

与本项目差异：上述项目都是「截图 + 视觉模型 + 模拟键鼠」的 CUA 路线；
本项目走「内存直读 + API 直调」路线（更快更可靠），视觉通道仅作兜底——
v0.8.0 后夜晚/电话/举报/射击全部纳入 API 直调，视觉兜底通道的覆盖差距进一步缩小。
