# 03 · 控制与决策模块设计（control + brain + 主循环）

> 模块定位：Computer Use Agent 的「手」（控制）与「脑」（决策），加上把观察—决策—执行串起来的「心跳」（主循环）。
> 状态：v0.2.0 已实现 · 单元测试 57/57 通过（全离线）。

## 1. 整体流水线回顾

```
游戏窗口 → 截图捕获(vision) → 视觉模型(vision) → 结构化状态 → 决策(brain) → 执行(control) → 游戏反馈 ↺
```

- 本阶段新增：**control**（鼠标/键盘）、**brain**（决策）、**agent_loop**（主循环）。
- 三个模块的关系：`agent_loop.step_once()` = `observe()` + `decide()` + `execute_decision()`。

## 2. 坐标系约定（贯穿全项目的关键规则）

| 坐标系 | 定义 | 使用者 |
|---|---|---|
| 截图坐标 | 与 `artifacts/screenshots/` 中 PNG 的像素一致；原点 = 窗口左上角（**含标题栏**），x 向右、y 向下 | 视觉模型输出 `point`、brain 的 click/move 参数、CLI 的 `--x/--y` |
| 屏幕坐标 | 物理像素绝对坐标 | 仅 control 模块内部使用 |

换算：`屏幕坐标 = 窗口左上角 + 截图坐标`（执行时自动完成，上层无感知）。
DPI 感知（Per-Monitor V2）在进程启动时声明，保证两套坐标不错位。

## 3. control 控制模块

| 文件 | 职责 |
|---|---|
| `control/mouse.py` | 底层鼠标：平滑移动（分步插值，兼容游戏悬停逻辑）、点击、滚轮 |
| `control/keyboard.py` | 底层键盘：按键（escape/enter/方向/字母/数字/F1-F12…）、ASCII 文本输入 |
| `control/controller.py` | 高层：窗口激活 + 坐标换算 + 安全校验 + 点击预览 |

### 3.1 安全机制（宁可拒绝，不误操作）
1. **执行前必须激活窗口并校验前台成功**——否则拒绝执行（避免把输入发给错误窗口）；
   直接 `SetForegroundWindow` 被系统拦截时，自动改用 `AttachThreadInput` 技巧重试。
2. **坐标越界直接拒绝**（附清晰的报错与坐标范围提示）。
3. **dry-run 模式**：只校验与记录，不产生任何真实输入（主循环默认 dry-run）。
4. **点击预览工作流**：`click --preview` 先生成带十字标记的全图 + 2 倍放大图，
   目视确认落点后再真实点击——这是给 AI 的"三思而后行"。
5. 每个动作返回 `ControlResult`（含执行前后细节与耗时），全部可审计。

## 4. brain 决策模块

| 文件 | 职责 |
|---|---|
| `brain/schema.py` | 决策契约校验：动作白名单 + 参数逐项规范化 |
| `brain/prompt.py` | 提示词：游戏上下文 + 工具表 + 坐标规则 + 当前观察 + 操作历史 |
| `brain/client.py` | 客户端：OpenAI 兼容文本接口 + 离线 Mock（支持样例文件） |
| `brain/brain.py` | decide() 流水线：解析 JSON + 校验 + 纠错重试 |

### 4.1 决策契约（稳定接口）
```json
{
  "action": "click | move | press_key | type_text | wait | stop",
  "params": {"x": 971, "y": 880},
  "reason": "顾客报价合适，点击收购按钮完成这笔交易",
  "confidence": 0.72
}
```
- **动作白名单**：白名单外的动作直接拒绝（防模型幻觉出不存在操作）；
- 参数规范化：坐标转整数 / 次数限制 1-10 / 等待限制 0.1-8s / 未知参数丢弃；
- 解析失败自动带纠错提示重试一次；原始输出全量落盘便于排查。

### 4.2 决策模型配置
`config/agent.json → brain`：`base_url` + `model` + 环境变量 `BRAIN_API_KEY`
（与视觉模型相互独立，可各用不同服务商；文本模型即可，成本远低于视觉模型）。

## 5. agent_loop 主循环

```
step_once()：观察(observe) → 决策(decide) → 执行(execute_decision) → 落盘 artifacts/steps/
run_loop()：按步数上限连续 step_once，自动携带最近操作历史
```

### 5.1 防卡死机制（项目核心目标）
| 机制 | 说明 |
|---|---|
| 默认 dry-run | `--live` 才真实操作；从机制上杜绝失控 |
| 步数上限 | `--max-steps` 硬性截断，绝无死循环 |
| 错误熔断 | 连续 2 步失败自动停止 |
| STOP 文件 | 在 `artifacts/` 下创建 `STOP` 文件，循环在下一步前优雅退出 |
| 每步落盘 | observation / decision / execution 全量 JSON，可回放审计 |

## 6. CLI 命令总表

| 命令 | 作用 |
|---|---|
| `list-windows` / `capture` / `observe` | 观察（见 docs/02） |
| `click --x --y [--preview] [--dry-run]` | 点击（截图坐标）；`--preview` 先目视确认 |
| `move --x --y [--dry-run]` | 移动鼠标（悬停） |
| `key --name escape [--times N]` | 按键 |
| `type --text hello` | 输入 ASCII 文本 |
| `step [--live] [--mock]` | 单步：观察→决策→执行 |
| `run --max-steps 5 [--live] [--mock]` | 连续步进 |

退出码：0 成功 / 1 未知错误 / 2 未找到窗口 / 3 截图失败 / 4 分析失败 / **5 控制失败**

## 7. 实测验证方式（无需游戏的自检闭环）

`scripts/make_test_window.py`（需带 tkinter 的 Python，如 Anaconda）会创建一个测试窗口：
- **被点击的位置留下红色圆环标记**，并显示最近一次点击坐标；
- **按键/输入会显示在反馈区**。

由此可验证完整闭环：
```
capture（截测试窗口）→ click --preview（确认落点）→ click（真实点击）
→ capture（新截图中应出现标记）→ key / type（反馈区显示）
```

### 7.1 实测记录（2026-10-13，DPI 修复后）

| 项目 | 结果 |
|---|---|
| 点击链路（截图坐标 → 屏幕坐标 → 窗口事件 → 画面标记） | ✅ **±1px 精确定位**（校准数值验证：目标 (450,420) → 标记 (449,420)；目标 (350,440) → 标记 (349,439)） |
| 主循环（观察→决策→执行）真实点击 | ✅ 全链路通过（`step --live`，新标记落点与决策坐标一致） |
| DPI 虚拟化兼容 | ✅ 已修复：DPI 不感知窗口（150% 缩放）自动识别换算系数 1.5（曾误判 1.0 导致点击偏移，根因：GetDpiForWindow 对不感知窗口恒返回 96，改用 GetDpiForMonitor） |
| 按键链路 | ⚠️ 事件已送达（窗口反馈处理器触发），但中文 Windows 的**输入法会干扰合成按键**（keysym 解析失败）；游戏通常自行处理输入，待游戏实测确认 |

配套调试工具（scripts/）：
- `make_test_window.py`：可交互自检窗口（点击标记 + 按键反馈；需带 tkinter 的 Python）
- `calibrate_click.py`：点击校准（一次运行完成 点击→截图→检测→对比）
- `find_markers.py`：红色标记检测（"点击后自动复核"的原型）
- `crop_image.py`：截图裁剪放大（核对 UI 细节）

## 8. 已知限制

| 编号 | 限制 | 说明 |
|---|---|---|
| C1 | 输入会真实抢占前台 | 激活窗口是点击/按键的前提（游戏必须能被激活） |
| C2 | 中文输入不支持；IME 可能干扰合成按键 | `type_text` 仅 ASCII；实测发现中文输入法会拦截字母键（表现为按键"无效"），自动化前可切换英文输入法或关闭 IME；游戏侧待实测 |
| C3 | 独占全屏仍不可用 | 控制与截图同理；保持窗口化/无边框 |
| C4 | 视觉模型的坐标是估算值 | 控制链路本身已验证 ±1px 精确；剩余误差来源是视觉模型的估算，用 `--preview` 目视确认 + `calibrate_click.py` 校准 + 后续"点击后自动复核"缓解 |
