# 游戏内模型设置面板（Ctrl+F9）

> v3.7 / 2026-11-10。解决的问题：换一个模型原来要退出游戏 → 找 `config/agent.json` 与 `.env`
> → 手改 JSON → 重开 agent。试错成本太高，尤其是模型商挂掉要临时切走的时候。

## §1 怎么用

1. 启动游戏（mod v3.7.0 起）；
2. **Ctrl+F9** 打开「模型设置」窗口（Ctrl+F10 仍是决策浮层，两个不冲突）；
3. 五个字段可改：

| 字段 | 说明 | 留空含义 |
|---|---|---|
| API 地址 | OpenAI 兼容根地址，一般以 `/v1` 结尾 | 沿用 `config/agent.json` 的 `brain.base_url` |
| 模型名 | 如 `gpt-4o-mini`、`tokeness/free` | 沿用 `brain.model` |
| API Key | 密码框显示，避免截图泄露 | 沿用 `.env` 的 `BRAIN_API_KEY` |
| Max Tokens | 整数 | 沿用 `brain.max_tokens` |
| Temperature | 0~1 小数 | 沿用 `brain.temperature` |

4. **保存并应用** → 写 `Mods/DeepSpaceBridge/model_config.ini`；
5. **测试连接** → 后台线程请求 `{地址}/models`，结果显示在窗口底部（不会卡游戏）；
6. **恢复默认** → 删除 ini，回到完全沿用 `config/agent.json`。

> 保存后**不影响正在跑的那一轮 agent**（进程启动时已读好配置）。
> 下一轮 `cli run` / `cli step` 才生效——窗口副标题也写了这句，避免误以为热切换。

## §2 为什么是 ini 而不是直接改 JSON

- C# 侧没有 JSON 库，手写 JSON 回写很容易把用户配置写坏（少个逗号整份失效）；
- ini 逐行 `key=value`，写坏最多影响一行，且人类可读、可手工修；
- Python 侧解析只要十几行，不引入依赖。

文件长这样：

```ini
# DeepSpace Bridge 模型配置（游戏内 Ctrl+F9 面板写入）
base_url=https://api.example.com/v1
model=gpt-4o-mini
api_key=sk-xxxx
max_tokens=4000
temperature=0.2
```

## §3 生效链路

```
游戏内面板 (C#)
   └─ 写 Mods/DeepSpaceBridge/model_config.ini
          ├─ C# 读：GET /modelconfig（面板自身回显、CLI 查询）
          └─ Python 读：load_config() → _apply_model_ini()
                  └─ 覆盖 brain.base_url / model / max_tokens / temperature
                  └─ get_api_key("brain") 优先用 ini 里的 api_key
```

**只作用于决策模型（brain）**。视觉通道保持配置文件里的设置——面板换上的可能是纯文本模型，
把它当图像模型用会直接报错。

## §4 定位 ini 的顺序

1. `config/agent.json` 的 `bridge.model_config`（显式路径，可指向任意位置）；
2. 环境变量 `GAME_AGENT_MODEL_INI`；
3. 自动探测：解析 Steam 的 `libraryfolders.vdf`，找
   `<库>/steamapps/common/Probably Stolen/Mods/DeepSpaceBridge/model_config.ini`。

三者都没有 → 视为"未配置"，全部沿用 `config/agent.json`（不会报错）。

## §5 命令行等价物

面板要在游戏里点；脚本化切换用命令更快（两者写同一个文件，不会打架）：

```bash
# 查看当前配置 + Python 侧叠加后的实际生效值
python -m game_agent.cli modelconf

# 切到另一个模型
python -m game_agent.cli modelconf \
  --base-url https://api.example.com/v1 \
  --model gpt-4o-mini \
  --api-key sk-xxxx

# 恢复默认（删除 ini）
python -m game_agent.cli modelconf --reset
```

游戏没开也能跑：会连不上桥，但仍然打印"当前实际生效"的值与 ini 路径。

## §6 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/modelconfig` | 当前配置（含文件路径与 `exists`，Key 只报是否已设置，不回显明文） |
| POST | `/modelconfig` | JSON 覆盖字段并落盘：`base_url`/`model`/`api_key`/`max_tokens`/`temperature` |
| POST | `/modelconfig/reset` | 删除 ini，回到默认 |

## §7 实现要点与坑

- **TMP_InputField 程序化创建**：需要手动指定 `textViewport`（RectMask2D 视口）与 `textComponent`，
  并给一个 `Image` 当 `targetGraphic`；字体走 `FontLoader.simplifiedChineseFont` 回退
  `notoSans`，与决策浮层一致。字体没加载到的那一帧直接返回，下一帧重建（不缓存半成品）。
- **网络绝不能在主线程等**：`Probe()` 放在后台 `Thread`，结果通过
  `MainThreadDispatcher.Enqueue` 回主线程刷 UI——主线程同步等 8 秒会把整个游戏卡住。
- **只从标题栏拖动**：整块面板接收拖动会抢走输入框的点击，输入框就点不进去了。
- **Key 用 `ContentType.Password`**：录屏/截图分享时不泄露。

## §9 实机验证与两个修正（v3.7.2）

### 9.1 布局错位（v3.7.1 修）

第一版手算 `anchoredPosition`，实机截图确认串位：输入框 x 少算左边距（与标签重叠 8px）、
第一行压住副标题、行距靠魔法数字。改为 `VerticalLayoutGroup` + `HorizontalLayoutGroup`
（每行 = 标签固定 112 + 输入框伸展），面板 520×508。**v3.7.2 实机截图确认对齐正常。**

顺带修交互：原来整块面板可拖，会抢走输入框的点击 → 改为只有顶部 34px 标题条能拖。

### 9.2 模型历史（v3.7.2 新增）

问题：面板只有「当前值」，换回用过的模型要重填一遍地址和名字。

做法：ini 里追加 `history_1..history_5`，格式 `base_url|model`：
- 每次保存把当前组合提到最前（去重、上限 5）；
- 面板底部「最近使用」一排按钮，点一下填回地址与模型名；
- **刻意不存 Key**：历史会出现在截图里，Key 不该跟着跑。

实机确认：写入两条后重启游戏，`GET /modelconfig` 返回
`history: ["https://n.tokeness.dev/v1|tokeness/free", "https://api.deepseek.com/v1|deepseek-chat"]`，
面板按钮正常显示与回填。

### 9.3 配置确实会持久化（排查结论）

实盘发现「每次都要重新搞」，先怀疑保存失败，实测：
- `POST /modelconfig` → 文件落盘（246 字节，4 个键）；
- 重启游戏 → `/modelconfig` 仍返回同一份值与 `exists=true`；
- `deploy_mod.py` 只拷 DLL 与 manifest，**不会覆盖 ini**（部署日志末尾那行是目录列表）。

所以"每次重搞"的真实原因是**面板没有历史、值显示依赖 ini 存在**，不是保存丢失。
