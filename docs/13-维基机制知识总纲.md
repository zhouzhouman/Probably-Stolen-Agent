# 深空当铺 · 机制知识总纲

> 本文由 `scripts/gen_knowledge_doc.py` 从 `knowledge/mechanics/` 的机制卡渲染而成，
> 与知识库同源同版本；改卡片后重跑即可同步，不要手改正文。

## 一、这套知识是怎么组织的

游戏维基（`probably-stolen.nicokobo.com/zh/wiki`）共抓取 **98 个 wiki 页面 + 3 篇攻略**。抓取后分三层落地：

| 层 | 位置 | 作用 | 规模 |
|---|---|---|---|
| L0 原始摘要 | `knowledge/wiki_raw/*.md` | 逐页保留原文要点、表格、公式，可审计 | 9 份 / 约 315KB |
| L1 机制卡 | `knowledge/mechanics/<category>/<id>.json` | 一张卡 = 一个可决策单元：触发条件 / 事实 / 该做 / 禁忌 / 后果 / 证据 | 见下方统计 |
| L2 检索器 | `game_agent/knowledge/` | 按当前局面挑 1~3 张卡，注入提示词 | 打分 + 类别去重 |

**为什么不把所有机制写进提示词**：静态机制说明曾经是 13.5KB / 284 行线性文本，
关键规则埋在中段（「批发是买入」写在里面，AI 照样点错、实盘净亏 62）。
拆成卡片后，每步只带当前相关的 1~3 张（约 1KB），既省 token 又能保证「此刻该看的那条」在注意力最近处。

## 二、一张卡包含什么

| 字段 | 回答的问题 |
|---|---|
| `facts` | 这条机制的规则与数值是什么（带证据） |
| `actions` | 此刻该做什么（可执行动作或中文指令） |
| `pitfalls` | 做错会怎样（反例 + 后果） |
| `effects` | 做完后状态怎么变（用于事后核对现金/库存差分） |
| `guards` | 前置条件（现金/声望/许可/容量） |
| `triggers` | 什么局面下该被检索出来（对 `/state` 求值的谓词） |
| `keywords` | 触发器覆盖不到时的兜底（只放专有名词） |
| `related` | 关联机制（同一条链上的其它卡） |

## 三、AI 在决策时怎么用这些卡

```
/state ──► 观察层(build_observation) ──► 检索器(MechanicRouter)
                                            │  触发器×2 + 关键词 + 置信×0.5
                                            │  同类别只取一张（避免日循环卡挤掉交易卡）
                                            ▼
                                 提示词【机制知识】段（≤3 张 / ≤1800 字）
                                            │
                                     LLM 产出动作 JSON
                                            │
                              校验层（白名单 + 8 个硬守卫 + 卡片 guards）
                                            │
                                        执行 ──► 用 effects 核对现金/库存差分
```

四个关键设计：

1. **触发为主、关键词为辅**：关键词只匹配观察里的**值**，不匹配字段名——
   否则 `rent_due` 这类字段名会让租金卡常驻。
2. **置信度只做同分微调**（×0.5）：否则「泛词命中 + 高置信」会压过真正的局面信号。
3. **同类别去重**：203 张卡里 `loop` 在任何营业/打烊局面都会触发，不去重会挤掉真正该看的卡。
4. **执行后核对**：卡片的 `effects` 用来判断动作是否真生效——本项目只认现金/库存差分，
   不认 `ok=true`（存在「返回成功但零成交」的动作）。

## 六、十二条最影响决策的机制

> 每条都直接改变下一步动作；数值以卡片为准，点击 id 可在 `knowledge/mechanics/` 查到全文。

### 1. 租金每期涨 5%/10% 并截断
`rent-increase-rate` · 置信 0.95
- 版本：✅ 已按 1.0 核实（decompile）
- **结论**：租金 7 天一期，下期只按本期租金乘 1.05（困难 1.10）后截去小数，欠租不进基数。
- 租金周期为 7 天，每期结算一次。
- 下期租金 = 本期租金 × 难度倍率后截去小数：cozy ×1.025、normal ×1.05、hard ×1.10、challenge ×1.10（PlayerStore.RentIncrease 用 (int) 强转截断）。
- 算例：本期租金 205 → cozy 210（205×1.025=210.125）、normal 215、hard 225；均截断，非四舍五入。
- **该做**：每期交租后立刻按 ×1.05 预估下期 rent_due
- **禁忌**：把开局租金当成全程固定支出，实际每 7 天按 5% 递增

### 2. 顾客预算加法公式
`budget-formula` · 置信 0.90
- 版本：⚠️ 未核实（依据 未知来源）
- **结论**：最终预算 = B + 三项以 B 为基数的加成各自取整后相加，不是连乘。
- 最终预算 = B + R(B × 好评加成) + R(B × 供应商加成) + R(B × 吸引力加成)，R 为取最近整数。
- 精确落在半整数时取偶数；每项分别取整，三项都以 B 为基数，加成相加而非连乘。
- 10% 档使用浮点近似系数，半整数附近可能有 1 点差异。
- **该做**：按公式估算顾客预算
- **禁忌**：用 B 的 (1+25%)×(1+50%) 连乘 → 高估（应为相加：240+60+120=420，非 450）。

### 3. 批发=整批全收换折扣
`wholesale-batch-deal` · 置信 0.90
- 版本：⚠️ 未核实（依据 未知来源）
- **结论**：批发必须买下卖家全部货，折扣率不固定，可逐件验货，别把折扣当保真。
- 批发定义：部分卖家在你买下其全部物品时给折扣；仍可逐件验货。
- wiki 明确「没有适用于所有卖家的固定折扣率」，不能预设固定百分比。
- 整批折扣不等于保真：食品券、药品的隐藏状态仍要用鉴定检查，无法使用的货同样占用现金与储位。
- **该做**：逐件验货
- **禁忌**：为折扣整批收 → 吃进无法使用的货，现金与储位双损。

### 4. 四种议价方向的代价
`nego-four-directions` · 置信 0.90
- 版本：⚠️ 未核实（依据 未知来源）
- **结论**：让利/加价必被接受但减少收入，抬价/压价可能被拒或顾客离开。
- 出售侧「提供折扣」= 你少收钱、利于顾客，必定被接受，同时提高顾客预算与交易声望收益。
- 出售侧「抬高售价」= 你多收钱、不利顾客，可能被拒绝或顾客离开，并降低其预算；成功后消耗声望。
- 购买侧「提出加价」= 你多付钱、利于顾客，必定被接受，提高交易声望收益。
- **该做**：出售侧提供折扣
- **禁忌**：把「购买」理解成自己在买 → 方向反了，让利变成让顾客占便宜。

### 5. 保费按总资产计价
`insurance-fee-formula` · 置信 0.95
- 版本：✅ 已按 1.0 核实（decompile）
- **结论**：保费＝3+⌊总资产/400⌋，再乘「被针对」×2 与难度倍率（cozy/normal ×1、hard ×2、challenge ×3）。
- 基础保费 3 信用点；游戏估算的总资产 W 每满 400 再加 1（W 含自有物品估值与现金，不是标价）。
- W＝3999 时保费 12；W＝4000 才升到 13。
- 结算顺序：①3＋⌊W÷400⌋ →②下层区「被针对」LLTARGET 生效则 ×2 →③再乘难度倍率 insuranceCostMultiplier：cozy 1 / normal 1 / hard 2 / challenge 3（Difficulty.cs:214/258/302/346；StoreService.cs:314 应用）。因此 hard＋被针对 = ×4，challenge＋被针对 = ×6。
- **该做**：睡前按当前 W 重算保费，不要沿用昨天的数字
- **禁忌**：用展示柜标价估算 W：W 是总资产（含现金）

### 6. 夜间失窃阈值公式
`night-theft-threshold` · 置信 0.95
- 版本：⚠️ 未核实（依据 decompile）
- **结论**：未投保夜数 N 每加 1 阈值 +5，基础 33、被针对 66，第 14 晚到 100%。
- 事件阈值基础 33；下层区「被针对」直接把基础值改为 66；治安贵宾 SEC_VIP 覆盖为 −100000（即不触发）。
- 再叠加「5 × N」（N 为累计未投保夜数，含当晚）；治安保护生效再减 16；阈值 <0 按 0%、>100 按 100%。
- 首个未投保夜晚 N＝1 时事件率 38%；第 14 晚达到 100%。这只是三步判定中的第 3 步，不是最终丢货率。
- **该做**：关店前把贵重品塞进暗格以脱离候选池
- **禁忌**：把 38% 当成最终丢货率：还要过警报那次 49%

### 7. 拾荒次数上限 5，受天赋加减
`scavenge-attempt-cap` · 置信 0.95
- 版本：⚠️ 未核实（依据 未知来源）
- **结论**：基础每晚 5 次搜索，熟练拾荒客 +2、骨关节炎每周 −1，算后不足 3 直接归零。
- 搜索次数上限基础为 5；剩余次数 = 上限 − 已用次数，拾荒结束时已用次数重置。
- 起始天赋「熟练的拾荒客」上限 +2（即 7）。
- 起始天赋「退行性骨关节炎」上限减去 floor((D−1)÷7)，D 为内部日计数：第一周不减，此后每周少 1 次。
- **该做**：出门前先算剩余次数，再决定带几件工具
- **禁忌**：以为每周固定 −1：实际是 floor((D−1)÷7)，第一周不减

### 8. 鱼片价值与电鳗发电
`fish-products-value` · 置信 0.92
- 版本：⚠️ 未核实（依据 未知来源）
- **结论**：大鱼片 900 千卡/135、鳗鱼片 500 千卡/170；电鳗每晚 1–3kJ 可给相邻电池充电。
- 鱼片基础价值：极小 100 千卡/13、小 200 千卡/26、标准 400 千卡/57、大 900 千卡/135；鳗鱼片小 250 千卡/85、鳗鱼片 500 千卡/170。
- 鱼片按实际可分配热量拆分，不能把目标体重直接换算成固定件数；剩余热量形成鱼碎，数量与价值随余量变化。
- 移植罗非鱼移植皮数量 = 实际体重 ÷ 200 克向下取整（450 克 → 2 份，600 克 → 3 份）；普通与沟渠罗非鱼不产这种移植皮。
- **该做**：出肉选鲟鱼/鳗鱼走高单价，罗非鱼走量
- **禁忌**：按目标体重估鱼片件数：实际按可分配热量拆分，会少

### 9. 盘查按最高等级处置
`inspection-severity-ladder` · 置信 0.95
- 版本：⚠️ 未核实（依据 未知来源）
- **结论**：处置看查获物里最严重的一件，罚款却按单位价值逐件相加。
- 处置按「被查获物品中最严重的一件」结算：高危级 → 无宽限时查封店铺并逮捕；有宽限时改走宽限对话并扣声望，但不保证保留查获货物。
- 高级 → 没收并罚款；中级 → 没收；只有赃物 → 没收赃物；低级 → 口头警告；什么都没查到 → 治安部声望 +3。
- 罚款算法：被查获物品的「单位价值」逐件相加，不是只看最严重那件。
- **该做**：高危级货必须进暗格或柜台后上锁
- **禁忌**：只藏最严重那件：其余违禁品仍按单位价值累加罚款

### 10. 枪证：300/600/900 三级链式前置
`gun-permit-tiers` · 置信 0.90
- 版本：⚠️ 未核实（依据 decompile）
- **结论**：三级枪证按违禁等级授权（300/600/900 信用点，逐级依赖）；持证清违禁标记，吊销移除许可且不自动补发。正式版 lockInDemo 判定零调用者，故不存在「Demo 锁」。
- GUN_PERMIT_I 300、GUN_PERMIT_II 600（需 I）、GUN_PERMIT_III 900（需 II）（NetworkUpgradeList.cs:76/78/80）。
- 卡内原有的「下发声望 30 / 60 / 90」与源码常量不符：正式版常量是 GUN_PERMIT_I_REP=20 / II_REP=50 / III_REP=80（NetworkUpgradeList.cs:150/152/154）。但这三个常量除声明外零引用，且只用于描述文案（NetworkUpgrade.ArgsGunPermitI/II/III），因此「20/50/80 是否真的是购买门槛」尚未被代码证明——按声望攒 20/50/80 也不能保证解锁。
- 持有后的吊销线是低于 0 / 30 / 60，由上门警官在对话结束时判定。
- **该做**：枪证可以买：两级前置满足、钱够 300/600/900 即可购（购买判定只走 IsReady()，NetworkUpgrade.cs:844-859），实际能否买到需实机确认
- **禁忌**：把「Demo 锁」当现行规则：lockInDemo=true 只是数据标记，判定函数 IsLockedInDemo()（NetworkUpgrade.cs:654-668）零调用者，不能据此断言买不到

### 11. 犯罪入账与派系折减
`crime-ledger-entry` · 置信 0.95
- 版本：⚠️ 未核实（依据 未知来源）
- **结论**：违禁按议定价值入账，赃物按议定价值×热度÷100，再吃派系与天赋修正。
- 销售带违禁标签物品：以该物品的议定价值计入对应走私罪名。
- 销售赃物：先算「议定价值 × 赃物热度 ÷ 100」，取整后计入销赃。
- 同一件货同时是赃物与违禁品时，两部分都可能入账。
- **该做**：优先卖卡特尔顾客（归零）或黑市顾客（÷2）
- **禁忌**：把脏水/伪劣化工算进犯罪总值：字段存在≠实际入账

### 12. 事件权重 180 不是概率
`market-event-weights` · 置信 0.90
- 版本：⚠️ 未核实（依据 未知来源）
- **结论**：15 项事件总权重 180，权重 15 的单次份额约 8.33%，不是「每天 15%」。
- 普通随机池共 15 项事件，总权重 180。
- 权重 15 的单次抽取份额 = 15 ÷ 180 ≈ 8.33%。
- 无活跃事件（50% 生成判定）时，权重 15 事件的当日判定概率 ≈ 4.17%。
- **该做**：按权重估算命中率
- **禁忌**：把「权重 15」读成「15% 概率」→ 高估约 1.8 倍。


## 七、机制 → 接口对照（v2.5）

每条机制都能对应一个**玩家操作**。三级分类：UI 级（点按钮/对话/拖拽）> 库存 API 级（容器间搬运，走接受校验）> 字段级（仅标记，不移动物品）。完整对照见 `docs/16-玩家操作接口对照表.md`。

| 机制面 | 接口 | 玩家操作 | 状态 |
|---|---|---|---|
| 远征 / 雇工 | `GET /expedition`、`expedition_send`、`hire_worker` | 夜间面板选点选人 | 已接门禁：未解锁如实拒绝（本存档 `unlocked=false`） |
| 机器与配方 | `GET /machines`、`machine_put`、`machine_take` | 打开机器投料/取产 | 库存 API 级，可用；拖拽迁移待做 |
| 彩票 | `dialog_choose {text}` | 与代表对话选号 | 选号接口就绪，等代表到场 |
| 治疗与戒瘾 | `night_service`、`dialog_choose {text}` | 夜间服务界面 / 医生对话 | 已解锁项可用 |
| 议价方向 | `open_negociation` + `object_action`/`ui_click` | 点谈判面板按钮 | 面板自绘，需坐标（`ui_hit` 先探） |
| 贿赂 | `dialog_choose {text}` | 盘查对话选「打点」分支 | 接口就绪，需盘查在场 |
| 许可购买 | 网络面板 | 平板电脑点条目 | 面板自绘，需坐标；未接 |

**通用输入层（v2.5 新增）**：`ui_hit`（射线查这一点归谁管）、`ui_click`（派发 pointerDown/Up/Click，等价玩家点击）、`object_action`（对具名对象 click / double_click / right_click）、`/ui/objects`（全量可点击清单，从 26 类白名单改为按接口全扫）。

**明确不做**：远征派遣、雇工招募、许可购买涉及内部方法直调，一律改为「未解锁就拒绝」，不用 `CreateExpedition` / `Hireling.Hire` 绕面板校验。
