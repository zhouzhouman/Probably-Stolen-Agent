## 夜间服务（services 索引）
- URL: https://probably-stolen.nicokobo.com/zh/wiki/services

### 机制要点
- 夜间服务共 **5 类**（索引页列出的卡片）：夜间扒窃、电力服务、清洁服务、保险服务、预警与人脉服务。
- 夜间扒窃是「肯定是偷的」Mod 新增的夜间活动：选择区域和目标，以手动或自动方式偷取物品，并在被发现前带着赃物返店（非原版机制）。
- 电力服务维持**照明与电网设备**；能量电池驱动的机器、充电器和能量方块需**分别检查**。
- 清洁服务夜间清空垃圾桶、打扫门面并维护客流；解锁**地下交易所**后，还负责按清单**交换物品**。
- 保险服务：当晚支付后，夜间被盗物品于**次晨返还**；睡前需核对承保、费用及黑市关系。
- 预警与人脉服务：按晚付费，可**介绍客源、预警常规检查、加快嫌疑下降**；三者用途与限制各不相同。
- 索引页对每项服务的描述均指向「睡前核对其当前状态」，说明服务是**按晚生效**而非一次性买断。

### 表格 / 数值
| 服务 | 主要作用 | 关键约束 |
|---|---|---|
| 电力服务 | 照明 + 电网设备运转 | 电池机器可脱离电网运行；警报需独立电源 |
| 清洁服务 | 清垃圾桶 + 门面 + 客流 | 桶内物品被**永久移除**；可换地下交易所物品 |
| 保险服务 | 次晨返还被盗物品 | 按晚加入/退出；黑市「拒保」则不可用 |
| 预警与人脉 | 介绍买家/卖家/违禁品买家、检查预警、善后 | 分项计费，各有冷却与限制 |

### 触发与前置
- 所有服务在**睡前**逐项开关，当晚结算。
- 清洁的地下交易所换物功能需先**解锁地下交易所**。

### 后果与风险
- 把垃圾桶当仓库 → 支付清洁后桶内物品**永久移除**。
- 把「已解锁」当成「已生效」→ 网络解锁后仍需当晚启用并付费。

### 与其他机制的关联
- 电力 ↔ 机器/充电器/能量方块/警报。
- 清洁 ↔ 垃圾等级 ↔ 吸引力 ↔ 客流。
- 保险 ↔ 夜间盗窃 ↔ 黑市关系 ↔ 卡特尔保护。
- 人脉 ↔ 客源/检查/嫌疑。

### 原文关键句
> 「电力服务维持照明与电网设备；能量电池驱动的机器、充电器和能量方块需分别检查。」
> 「当晚支付保险后，夜间被盗物品会于次晨返还；睡前核对承保、费用及黑市关系。」

## 电力服务（power-service）
- URL: https://probably-stolen.nicokobo.com/zh/wiki/services/power-service

### 机制要点
- 标题即结论：**「缴电费与装电池是两件事」**——两者互不替代。
- 睡前可以开关当晚的电力服务；支付后维持店内**照明与电网设备**运转。
- **未付电费时灯光变暗，但使用能量电池供电的机器仍可运行**，前提是：自身电池有电 **且** 满足工作条件。
- 四种夜间供能方式被明确区分：能量电池（energy_credit）、充电器（recharger）、能量方块 PowerBloc（powerblock）、警报系统（security_alarm）。
- **能量电池**：可充电的独立电源，兼容多数机器；需装入设备要求的位置。
- **充电器**：店内**已供电**时，每晚为内部**每块**电池恢复 **3 点**电量；商用级供电升级后为 **6 点**。
- **能量方块（PowerBloc）**：店内已供电时，每晚给**相邻电池或相邻机器内电池**恢复 **2 点**电量；商用级供电升级后为 **4 点**，**排除充电器**；效果**可叠加**。
- **警报系统**需要**自己的独立电源**；缴纳店铺电费**不能替代**安装电源。
- 两种相关网络升级：**偷电**（POWER_HIJACK）明确使夜间电力服务**免费**，夜间日志也有「依靠偷电在停电时仍保持供电」的结果。
- **商用级供电单元**（COMMERCIAL_POWER）：基础解锁费用 **350 信用点**，使充电量提高 **100%**：充电器每块电池每晚 3 → 6 点，能量方块 2 → 4 点。它**不免除电费**，仍需满足当晚供电与摆放条件。
- 上述充电量、商用级升级费用与供电条件于 **2026-10-22** 对原版 Demo **Steam Build 26017150** 静态核对，未做游戏内实测。
- 普通电费公式：**5＋floor(D÷10)** 信用点；困难模式将该结果 **乘 2**。D 是计费时的内部日计数，floor 为向下取整。
- 例：**D＝20 → 普通 7、困难 14**。
- 偷电解锁后将费用**置为 0**，并把电力服务**置为使用中**；**停电事件也会把显示费用置为 0**，所以「免费」本身不能证明当晚有电。
- 这句是「服务费用重算规则」，**初始配置与后续报价应区分**（不要把开局初始化价当每晚固定价）。
- 停工时排查顺序：先看夜间日志是**欠费断电**还是**停电**，再查电池余量、充电布局、机器原料。
- 只有**一台**设备不工作 → 优先查该设备；**多台**同时出问题 → 再核对服务与停电。
- **已缴电费不保证机器已投料，也不保证独立电池已充满**。

### 表格 / 数值
| 项目 | 数值 | 说明 |
|---|---:|---|
| 电费公式（普通） | 5＋floor(D÷10) | D＝20 → 7 |
| 电费公式（困难） | ×2 | D＝20 → 14 |
| 充电器（电网已供） | 3 点/块/晚 | 商用级后 6 点 |
| 能量方块 PowerBloc | 2 点/晚 | 商用级后 4 点；排除充电器；可叠加 |
| 商用级供电单元 | 350 信用点 | 充电量 +100%，不免电费 |
| 偷电（POWER_HIJACK） | 电费置 0 | 电力服务被置为使用中 |
| 警报系统 | 需独立电源 | 电费不能替代 |

### 触发与前置
- 电池机器在断电下运行的前置：**电池有电 + 满足工作条件**。
- 充电器/能量方块生效的前置：**店内当晚已供电**（已付电费或偷电）。
- 商用级供电单元：需**当晚供电 + 摆放条件**，不免电费。

### 后果与风险
- 看到服务费用为 0 就认为「今晚有电」→ 停电事件同样把费用显示为 0。
- 断电时以为所有机器都停 → 电池机器仍能跑，误判为「服务没生效」。
- 以为缴电费就给警报供电 → 警报必须自装电源。
- 以为商用级供电单元包电费 → 它只提充电量。

### 与其他机制的关联
- 店铺设施升级：POWER_HIJACK 300 / COMMERCIAL_POWER 350（见 shop-network）。
- 夜间盗窃：警报系统独立电源（见 theft-and-insurance）。
- 生产：机器投料与产物空间（见 01-trade-loop 的生产段）。

> 「未付时灯光变暗，使用能量电池供电的机器仍可运行，前提是自身电池有电且满足工作条件。」
> 「普通电费为 5＋floor(D÷10) 信用点；困难模式将该结果乘 2。」
> 「偷电解锁后将费用置为 0，并把电力服务置为使用中；停电事件也会把显示费用置为 0，所以『免费』本身不能证明当晚有电。」

## 清洁服务（janitorial-service）
- URL: https://probably-stolen.nicokobo.com/zh/wiki/services/janitorial-service

### 机制要点
- 睡前启用并支付清洁服务后：**垃圾桶会清空**、**店铺门面得到清理**。
- 连续多天不打扫会**降低吸引力**；夜间日志的措辞会从「少量垃圾影响客流」逐步升级到「垃圾和瓦砾严重阻碍进店」。
- 店铺**被破坏**后，清洁可处理留下的脏乱、让顾客恢复到访意愿，但**这次清理费用更高**——不要只按平常单晚费用留钱。
- **垃圾桶不是仓库**：垃圾桶说明明确「支付清洁服务后，桶内物品会在夜间被永久移除」。
- 睡前必须把误放的工具、商品、原料从垃圾桶**取回**。
- 地下交易所是**已解锁后**的专门用途，三步流程：①看当前交换清单（部分要求**每隔几天变化**）→ ②把清单要求的物品放入垃圾桶 → ③当晚使用清洁服务，次晨检查换回的物品。
- 清洁工对话说明这种交换**不会被治安部追踪**；但这**不使店内其他违禁品或既有证据失效**。
- 没有取得交易所资格时，**不要把普通丢弃当作一定有回报的交换**。
- 黑市「**不受信任**」效果会使清洁服务**费用翻倍**，并**禁止使用地下交易所**。
- 清洁费公式（D 为计费时内部日计数，floor 向下取整，单位信用点）：
  - 门面**未遭破坏**：**3＋floor(D÷10)**
  - 门面**遭破坏**：**75＋floor(D÷10)**
  - **Sawyer Crew 天赋，未遭破坏**：**0**
  - **Sawyer Crew 天赋，遭破坏**：**30＋floor(D÷5)**
- 黑市「不受信任」把上表结果**再乘 2**。
- 该重算分支**没有额外的困难模式清洁倍率**；不要把开局服务初始化加价当成每天固定叠加。
- 例：**D＝20 → 普通清洁 5，遭破坏 77**。
- 脏乱累计公式：清洁服务**已解锁后**，每次进入未使用分支，**G＝min(G＋2, 10)**；清洁会把 **G 清零**。
- 已开放的地下交易所**先处理交换，再清空垃圾**。
- 扣吸引力规则：**G 不超过 2 时不扣**；超过 2 时**每级扣除基础吸引力的 5%**，扣除额**截去小数**。
- **投影设备加成另加，不参与这笔扣减**。
- 以基础吸引力 **B＝250、无投影加成**为例：1 晚 G=2 → 250（不扣）；2 晚 G=4 → 200；3 晚 G=6 → 175；4 晚 G=8 → 150；5 晚及以上 G=10 → 125。
- 结论句：**第一晚不扣；第二晚直接扣基础值的 20%**；此机制**最高扣基础值的 50%**。

### 表格 / 数值
| 条件 | 清洁费（信用点） | 备注 |
|---|---:|---|
| 门面未遭破坏 | 3＋floor(D÷10) | D＝20 → 5 |
| 门面遭破坏 | 75＋floor(D÷10) | D＝20 → 77 |
| Sawyer Crew，未遭破坏 | 0 | 天赋免费 |
| Sawyer Crew，遭破坏 | 30＋floor(D÷5) | 分母是 5 不是 10 |
| 黑市「不受信任」 | 上表 ×2 | 并禁用地下交易所 |

| 连续漏清洁 | 脏乱 G | B＝250 时吸引力 |
|---|---:|---:|
| 1 晚 | 2 | 250 |
| 2 晚 | 4 | 200 |
| 3 晚 | 6 | 175 |
| 4 晚 | 8 | 150 |
| 5 晚及以上 | 10 | 125 |

### 触发与前置
- 清洁结算前置：睡前**启用并支付**。
- 垃圾桶换物前置：**已解锁地下交易所** + 放入清单要求的物品 + 当晚使用清洁服务。
- 公式生效前提：清洁服务**已解锁**（未解锁不进入 G 累计分支）。
- 版本注记：2026-09-19 解包核对本地 Demo **Steam build 25382790**；一般机制参考 GAME_GUIDE 第 2 章（2026-09-14 快照）；**D 与界面日期的偏移未核实**。

### 后果与风险
- 把工具/商品留垃圾桶 → 夜间**永久移除**，无法找回。
- 店铺被破坏后仍按 5 信用点留钱 → 实际需 77。
- 连续两晚不清洁 → 直接损失基础吸引力 20%，不是 5%。
- 黑市「不受信任」期间想做交易所换物 → 功能被禁用，费用还翻倍。

### 与其他机制的关联
- 垃圾等级字段 `visible_info.rent.garbage_level`；吸引力 `visible_info.economy.attractiveness`。
- 店铺被破坏 ↔ 风险主题（见 02-risk-security）。
- 地下交易所 ↔ 黑市关系（不受信任/拒保）。
- 投影设备加成不参与扣减（独立加成项）。

### 原文关键句
> 「支付清洁服务后，桶内物品会在夜间被永久移除。」
> 「脏乱等级 G＝min(G＋2, 10)；清洁会把 G 清零。……不超过 2 时不扣吸引力；超过 2 时，每级扣除基础吸引力的 5%，扣除额截去小数。」

## 保险服务（insurance-service）
- URL: https://probably-stolen.nicokobo.com/zh/wiki/services/insurance-service

### 机制要点
- **Joe Wild** 提供按晚选择的保险，睡前可以**加入或退出**。
- 当前服务说明：**支付保险后，当晚被盗的物品会在第二天早晨返还**；对应夜间日志描述 Wild 的人找到小偷并带回物品。
- 因此**不用按商品标价估算一笔现金赔款**，也**不要将预计返还物当成已经到手的缴租资金**。
- 这项说明**只针对夜间盗窃**，不能延伸成检查扣押、垃圾桶清空、生产损耗或任何失物都能追回。
- 睡前核对三件事：当晚保险**已启用**、服务**仍可用**、现金足以承担**当前费用**。
- 次晨看日志：**已支付 = 受保**；未支付会显示**距离上次受保经过的天数**（`insurance_days_without`）。
- 若发生盗窃，核对三样：被盗条目、保险追回记录、实际库存。
- 下层区「**被针对**」效果：增加被小偷盯上的频率 **并** 提高保险费用，保险费用**倍率为 2**。
- 黑市「**拒保**」：直接使保险服务**不可用**。
- 页面强调：**「费用变高」和「无法投保」是两种不同状态**。
- 分工：**警报系统**负责降低盗窃风险，**保险**负责盗窃后的物品返还。
- 保费结算顺序：①估算总资产 **W** → ②**基础费 3 信用点；W 每满 400 再加 1** → ③下层区「被针对」若生效，**乘 2** → ④困难模式若启用，**再乘 2**。
- **W 是游戏估算的总资产**，包含参与统计的自有物品估值**和现金**，**不是展示柜标价**。
- 例：**W＝3999 → 基础费 12；到 4000 才升为 13**（即 3＋floor(W÷400)）。
- 完整库存覆盖与单件估值修正未展开，**不能直接拿出售标价相加代替 W**。
- 会改变普通保险可用性的状态：**服务尚未介绍、黑市拒保、卡特尔保护已解锁**。
- 当前**受保分支**：把**连续未投保计数归零**，并有 **6% 的追回叙事日志判定**；该分支**没有执行普通未投保路径的物品移除**。
- **6% 不是受保后永久丢货率，也不是现金赔款率**。

### 表格 / 数值
| 项目 | 数值 | 说明 |
|---|---:|---|
| 基础保费 | 3 信用点 | W 每满 400 再加 1 |
| 保费公式 | 3＋floor(W÷400) | W＝4000 → 13；W＝3999 → 12 |
| 下层区「被针对」 | ×2 | 同时提高被偷频率 |
| 困难模式 | ×2 | 在「被针对」之后结算 |
| 受保分支追回判定 | 6% | 叙事日志判定，非丢货率 |
| 受保分支 | 连续未投保计数归零 | 不执行普通未投保移除 |
| 黑市「拒保」 | 服务不可用 | 与「涨价」不同状态 |

### 触发与前置
- 生效前置：**睡前支付 + 当晚服务可用**。
- 不可用状态：服务未介绍 / 黑市拒保 / 卡特尔保护已解锁。
- W 的取值口径：自有物品估值 + 现金（非标价）。

### 后果与风险
- 把「保险」当现金赔偿 → 租金日现金缺口，返还物不能抵租。
- 用展示柜标价估算 W → 保费预算偏低。
- 以为买保险就不会被偷 → 保险是事后追回，不阻止入室盗窃。
- 以为 6% 是丢货率 → 误判风险。

### 与其他机制的关联
- 夜间盗窃判定链：terms/theft-and-insurance。
- 警报系统：独立电源、降低盗窃率。
- 卡特尔保护：启用时跳过普通夜间盗窃分支，并影响保险可用性。
- 租金：返还物 ≠ 现金（见 rent-lease）。

### 原文关键句
> 「支付保险后，当晚被盗的物品会在第二天早晨返还。」
> 「W 是游戏估算的总资产，包含参与统计的自有物品估值和现金，不是展示柜标价。」
> 「当前受保分支将连续未投保计数归零，并有 6% 的追回叙事日志判定。」

## 预警与人脉服务（contact-services）
- URL: https://probably-stolen.nicokobo.com/zh/wiki/services/contact-services

### 机制要点
- **Wilds 网络中的服务型项目解锁后，仍需当晚付费启用**才会提供帮助；睡前可**逐项开关**。
- 它们与「拨打名片上的电话联系供应商」是**不同入口**（网络购买 ≠ 电话联系）。

## 防盗与保险（theft-and-insurance，下钻，仅摘相关段）
- URL: https://probably-stolen.nicokobo.com/zh/wiki/terms/theft-and-insurance

### 机制要点
- 分工：**警报**降低普通夜间盗窃**风险**；**保险**负责当晚失窃后的**次晨追回**。
- **警报可能失效，保险也不阻止入室盗窃**；两者均按当晚实际状态核对。
- 警报设置：打开警报查看**电源槽、模组槽、当前防盗率**；**店铺电力服务已缴费 ≠ 警报已装好电源**。
- 警报说明书：**模组效率**对应耗电，**性能**对应防盗率加成；**品质对这项模组效果无影响**。
- 柜台下用于**举报当前顾客**的治安呼叫按钮，与夜间警报设备**用途不同**。
- 普通未投保分支的判定顺序（任一提前返回即不进入失窃掷骰）：
  1. 状态判定：**保险服务未解锁、卡特尔保护启用、或拥有 Alert 天赋** → 提前返回。
  2. 看当晚保险：**已投保 → 走追回日志分支，连续未投保夜数清零**。
  3. 累计未投保夜数：未投保且未提前返回 → **连续夜数 N 加 1**，再算事件率。
  4. 看警报：事件掷骰**通过且警报有效** → **再掷一次**是否被警报拦截。
  5. 选物品：事件通过且警报未拦截 → 从可盗候选中**随机选一件**；**没有候选就不会从该池丢货**。
- 事件率调整：**基础 33**；若下层区「被针对」则**改为 66**；**治安贵宾 SEC_VIP 把基础值覆盖为 −100000**；**连续未投保加 5×N**；**N 已包含当晚治安保护生效减 16**。
- 抽取 **0–99 的整数**，**小于最终阈值才通过**；阈值低于 0 或高于 100 时，实际概率按 **0%** 或 **100%** 处理。
- 无修正时：**首个未投保夜晚 N＝1，事件率 38%**；**第 14 晚达到 100%**。这只是**第 3 步**，**并非最终丢货率**。
- 警报：显示防盗值 = **50＋当前性能加成**，**最低显示 0**；**实际拦截概率比显示值多 1 个百分点**，**最高 100%**。
- 因此**显示 50 → 拦截率 51%**；**显示 99 时已能拦截全部随机结果**。
- **警报只影响这里的普通夜间盗窃**。
- 选物品规则：从自有物品筛候选后**随机选一件**，**不会固定偷最贵的**。
- 排除项：**文件、容器本体、机器、当前价值为 0 的物品、走私者暗格内的物品**；带**重要、锁定、锁后物品、卡住模组**等保护标签的；或**父库存同时禁止放入和取出**的。
- 特殊例外：带「**强制可抵押**」标签的物品**会先通过筛选**（即可能被偷）。
- **容器本体被排除，不代表其内容物都受保护**。
- 算例：普通首晚触发率 38%、有效警报显示 50、存在候选且无特殊分支 → **38%×49%＝18.62%**；这是带前置条件的算例，**不是全游戏统一失窃率**。
- 卡特尔保护再次确认：**启用时跳过普通夜间盗窃分支**（第 1 步提前返回）；**不影响检查、没收等其他损失**。

### 表格 / 数值
| 项目 | 数值 | 说明 |
|---|---:|---|
| 未投保事件率基础值 | 33 | 「被针对」改为 66 |
| 连续未投保加成 | +5×N | N 含治安保护生效减 16 |
| 治安贵宾 SEC_VIP | 基础值 −100000 | 覆盖为必不触发 |
| 首晚（N＝1）事件率 | 38% | 仅第 3 步 |
| 第 14 晚 | 100% | 阈值上限 |
| 警报显示值 | 50＋性能加成 | 最低 0 |
| 警报实际拦截 | 显示值 +1% | 显示 50 → 51% |
| 两次判定合成 | 38%×49%＝18.62% | 带前置算例 |

### 触发与前置
- 提前返回三条件：**保险未解锁 / 卡特尔保护启用 / Alert 天赋**。
- 警报拦截生效前置：**事件掷骰通过 + 警报有效（有独立电源）**。
- 丢货前置：**存在可盗候选**。

### 后果与风险
- 以为保险能阻止盗窃 → 它只在次晨追回。
- 认为「容器被排除所以内容安全」→ 内容物仍可能被偷。
- 把 51% 当成 50% → 少算 1 个百分点。
- 把 38% 当最终丢货率 → 未乘警报拦截率。

### 与其他机制的关联
- insurance-service（费用与返还语义）、power-service（警报电源）。
- 卡特尔保护 mandatory（contact-services）。
- 治安贵宾 SEC_VIP / 下层区「被针对」↔ 声望与派系（见 03）。
- 检查扣押 ≠ 盗窃（不同机制）。

### 原文关键句
> 「先看状态：保险服务未解锁、卡特尔保护启用或拥有 Alert 天赋 → 提前返回。」
> 「实际拦截概率比显示值多 1 个百分点，最高按 100% 处理。因此显示 50 时拦截率为 51%。」
> 「容器本体被排除，不代表其内容物都受保护。」
