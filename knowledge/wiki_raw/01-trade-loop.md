> 抓取时间：2026-10-24 ｜ 覆盖页面：13 个（11 个指定页 + 2 个下钻页）

## 每日流程（daily-cycle）
- URL: https://probably-stolen.nicokobo.com/zh/wiki/terms/daily-cycle

### 机制要点
- 一日的固定顺序为四段：**早晨整理 → 开门接客 → 打烊准备 → 睡觉结算**；打烊与睡觉是**两个步骤**，不是同一个动作。
- 早晨第一件事是查看**夜间日志**，核对四项：机器产物、失物、服务状态、伤口。
- 早晨第二件事是看**报纸**，确认当前生效的市场事件，再核对现金、租金与借款到期时间。
- 现金分配顺序被明确要求：先留出「账单备用金」（租金/还款），剩余现金才可用于进货。
- **库存标价不能拿来交租**：账面货物价值不构成支付能力。
- 开门前要做的三件事：把想卖的商品放进**展示柜**、整理柜台与储物空间、再打开卷帘门。
- 展示柜只影响客源（招来哪类买家），**不保证下一位顾客就买走指定商品**。
- 营业中按铃接待下一位顾客；接待顺序固定为「先读来意 → 再处理买卖/鉴定/订单/检查」。
- 交易时必须核对三项：顾客需求、顾客预算、货物状态。
- 建议每次大额进货前重新看一次现金，避免「还没到缴租日就把备用金全换成库存」。
- 打烊后睡前检查清单含五块：**生产**（材料放进机器**内部**、检查电源/设备/产物空间）、**服务**（夜间服务可逐晚开关，核对费用）、**防盗**（警报需已启用且备**独立电源**，保险看实际覆盖）、**健康**（伤口与成瘾）、**外出**（打烊后才可外出，需先确认携带与带回空间）。
- 只有关闭店铺后才能用**睡袋**睡觉；**营业时不能睡觉**。
- 睡觉即推进一天并**自动存档**；夜间生产、服务与事件的结果要到次日才能核对。
- 睡眠同时结算：伤口、戒断、哨兵疾病。
- 打烊后外出有代价：**次日少来 1 名顾客**（原文链到「夜间外出」页）。
- 新手建议：第一轮只观察一台现有机器，睡前记录投入，次日核对产出与日志。

### 表格 / 数值
| 阶段 | 关键动作 | 约束 |
|---|---|---:|
| 早晨 | 夜间日志、报纸、现金/租金核对 | 备用金优先 |
| 开门前 | 展示柜陈列、整理柜台、开卷帘门 | 开门后加入的展示次日才生效（见展示柜页） |
| 营业 | 按铃 → 读来意 → 交易 | 营业中不能睡觉 |
| 打烊后 | 生产/服务/防盗/健康/外出 | 外出 → 次日少 1 名顾客 |
| 睡觉 | 睡袋 → 推进一天 + 自动存档 | 需先关闭店铺 |

### 触发与前置
- 睡觉前置：店铺已关闭（CLOSED）；营业状态（OPEN）下无法睡觉。
- 生产结算前置：材料必须在机器**内部**、电源开启、产物空间足够。
- 夜间外出前置：已打烊；需预留携带/带回空间。

### 后果与风险
- 没留备用金 → 租金到期现金不足（库存不能抵租）。
- 展示柜误判为「保底成交」→ 备货错品类。
- 营业中想换日 → 必须先打烊，多一步操作。

### 与其他机制的关联
- 租金与借款：rent-and-loans（备用金、rent_due）。
- 展示柜：showcase（客源、品类价值、名额）。
- 夜间外出：afterhours（次日少 1 名顾客）。
- 机器供电：machine-operation、power-service。

> 「库存标价不能拿来交租。」

## 买卖与议价（trading-and-bargaining）
- URL: https://probably-stolen.nicokobo.com/zh/wiki/terms/trading-and-bargaining

### 机制要点
- 顾客来意语义：「购买」= 顾客向你买货；「出售」= 顾客把货卖给你。议价按钮上则**直接写你正在买还是卖**，两套主语相反，容易看错。
- 交易前置动作：把货物拖到**谈判柜台**，或 **Ctrl＋单击**快速转移，再打开交易界面。
- **物品上台不代表成交**，仍需完成成交操作。
- 议价前必须核对三件事：顾客要的品类、拒收范围、剩余预算。
- 鉴定服务、采购交货、以物易物各有独立流程，**不能套用普通零售报价**。
- 四种议价方向及其代价（见下表）：让利（卖侧降价）与加价（买侧提价）都是「利于顾客 → 必定接受」；抬价（卖侧涨价）与压价（买侧要折扣）都是「利于自己 → 可能拒绝/离开」。
- 让利会**增加顾客预算**并提高交易声望收益；抬价会**减少顾客预算**。
- 争利（抬价/压价）成功后会**消耗声望**。
- 声望决定「争取有利价格」的接受概率，界面同时给出接受/拒绝/离开概率与「每交易 1000 信用点的预计声望」。
- 判断标准：不能只看单件差价，要把差价与「每 1000 信用点预计声望」一起看。
- 「必定接受」只针对议价条件，**不会让顾客收下其原本拒收的品类**。
- 声望倍率分档：p≤10% 让利 +1 / 争利 −3；10%<p≤25% +1.5 / −6；25%<p≤50% +2.5 / −12；p>50% +3 / −16。
- 让利时奖励**加到原倍率 B 上**（B=1 时让利 10% → 2，让利 25% → 2.5）；争利成功则**把该方向倍率直接设为负值**（争利 10% → −3），不是从 B 里扣一点。
- 倍率不是固定声望点数，最终还与**交易额**有关。
- 「同步」神经活性香水：对当前顾客 **15%** 交易增益；「本源」费洛蒙香水：**25%**；两者**不可叠加**（费洛蒙属违禁香水）。
- 香水增益不等于「所有物品按基础价值 +15%/+25% 成交」；零售加价另有合法性、物品与顾客接受条件。
- 身份类施压与货物类对质是两套系统：「敲诈勒索」针对**罪犯**，「威胁」针对**改造体**；对非罪犯敲诈必定失败，把普通顾客当改造体威胁也会失败并损失声望。
- **不要用商品真假推断顾客身份。**

### 表格 / 数值
| 方向 | 操作 | 对顾客 | 结果 | 声望 |
|---|---|---|---|---:|
| 出售 | 提供折扣 | 少收钱（有利） | 必定接受 | 预算↑、声望收益↑ |
| 出售 | 抬高售价 | 多收钱（不利） | 可能拒绝/离开 | 预算↓，成功后消耗声望 |
| 购买 | 提出加价 | 多付钱（有利） | 必定接受 | 声望收益↑ |
| 购买 | 要求折扣 | 少付钱（不利） | 可能拒绝 | 成功后消耗声望 |

| 让利/争利比例 p | 主动让利：倍率 | 争利成功：倍率 |
|---|---:|---:|
| p ≤ 10% | +1 | −3 |
| 10% < p ≤ 25% | +1.5 | −6 |
| 25% < p < 50% | +2.5 | −12 |
| p > 50% | +3 | −16 |

| 道具 | 交易增益 | 备注 |
|---|---:|---|
| 「同步」神经活性香水 neuroactive_perfume | 15% | 仅对当前顾客 |
| 「本源」费洛蒙香水 pheromone_perfume | 25% | 违禁；与 15% 不可叠加 |

### 触发与前置
- 议价面板打开：`nego_open = true`；批发按钮 `nego_buttons.wholesale`；接受报价 `nego_buttons.accept_offer`。
  （2026-11-15 更正：本行原写「整批接受 `accept_multiple`」——正式版谈判面板只有
  `primaryButton`/`secondaryButton` 两个大按钮，`BridgeApi.cs:1185-1191` 只发射
  `primary`/`secondary`/`wholesale`/`accept_offer` 四键，`accept_multiple` 不存在。）
- 争利前需要声望支撑，否则拒绝/离开概率上升。
- 香水必须在与**当前顾客**交易时生效。

### 后果与风险
- 反复加码 = 提高离开概率，对有指定需求或稀缺库存的顾客代价最大。
- 让利换声望若未实际成交，**不算已获得声望**（只有提出条件、没有交易）。
- 在错误的高估价上打折（未先鉴定）→ 双重亏损。
- 把真假当身份证据去敲诈/威胁 → 必定失败 + 掉声望。

### 与其他机制的关联
- 顾客预算（打折会提高预算）；物品鉴定（先鉴定再议价）；对质（货物异常）；派系声望。

## 顾客预算（customer-budgets）
- URL: https://probably-stolen.nicokobo.com/zh/wiki/terms/customer-budgets

### 机制要点
- 普通买家预算公式：**最终预算 = B + R(B × 好评加成) + R(B × 供应商加成) + R(B × 吸引力加成)**。
- `R` 表示取最近整数；**精确落在半整数时取偶数**（banker's rounding）。
- 三项加成**分别取整**，且都以 B 为基数，加成相加（不是连乘）。
- 10% 档使用浮点近似系数，半整数附近可能有 **1 点**差异。
- 「好评如潮」：**+B 的 25%**，解锁门槛是**声望上层区达到 100**。
- 「可靠供应商」：**+B 的 50%**，解锁门槛是**治安部达到 80**。
- 预算加成**不再按买家派系筛选**；声望只通过「是否解锁特权」生效，不逐点折现。
- 吸引力加成**只取当前最高档**，同档内继续提升吸引力不加钱（见下表）。
- 算例：B=240、吸引力 600、已解锁「好评如潮」→ 240+60+120=**420**；再解锁「可靠供应商」→ 再 +120，合计 **540**。
- 吸引力档位表：<300 → +0；300–449 → +10% B；450–599 → +25% B；600–749 → +50% B；750–899 → +75% B；900+ → +100% B。
- 已核实五种买家基础预算（克雷迪，D 为生成顾客时的**内部日计数**，与界面日期的偏移未核实；R0–N 含两端）：
  - 囤水者：`D + 500 + R0–100`（D=14 → 514–614）
  - 买水的顾客：`145 + 舍去小数(D÷4) + R0–50`（D=14 → 148–198）
  - 上层区私人厨师：`D + 400 + R0–100`（D=14 → 414–514）
  - 买水的拾荒客：`175`（固定）
  - 水相关事件的普通买家：`150 + R0–50`（→ 150–200）
- 预算变大**不保证接受全部库存**：顾客仍受品类、品质、数量、交易意图要求限制。
- 买家预算 ≠ 卖家现金 ≠ 采购订单金额，是三套不同规则。
- 剧情/服务类预算入口另有规则，不能套用这些公式。
- 展示柜「品类陈列价值」与「店铺吸引力」是两个不同数值；高价档门槛的「350」是**陈列品类价值**，不能读成「吸引力 350」。

### 表格 / 数值
| 吸引力当前值 | 预算加成 |
|---|---:|
| < 300 | +0 |
| 300–449 | +10% B |
| 450–599 | +25% B |
| 600–749 | +50% B |
| 750–899 | +75% B |
| ≥ 900 | +100% B |

| 特权 | 加成 | 解锁条件 |
|---|---:|---|
| 好评如潮 | +25% B | 声望上层区 ≥ 100 |
| 可靠供应商 | +50% B | 治安部 ≥ 80 |

| 买家类型 | 基础预算 B | D=14 时范围 |
|---|---|---:|
| 囤水者 | D + 500 + R0–100 | 514–614 |
| 买水的顾客 | 145 + ⌊D÷4⌋ + R0–50 | 148–198 |
| 上层区私人厨师 | D + 400 + R0–100 | 414–514 |
| 买水的拾荒客 | 175 | 175 |
| 水相关事件的普通买家 | 150 + R0–50 | 150–200 |

### 触发与前置
- 加法只在**生成顾客时**计算一次；D 取生成当天的内部日计数。
- 特权必须**已解锁**才计入；口碑/声望本身不直接加钱。
- 吸引力档位跨档才变；脏乱会先扣吸引力（见展示柜页）。

### 后果与风险
- 用「基础预算」估成交额 → 漏算三项加成，低估 25%~100%+。
- 用「吸引力 350」理解高价来客门槛 → 实际门槛是品类陈列价值 350（日用品 300）。
- 预算高就大量推销 → 顾客仍可能因品类/品质/数量拒收。

### 与其他机制的关联
- 展示柜（吸引力、品类价值、名额）；清洁服务（脏乱扣吸引力）；买卖与议价（让利会改预算）；买水的顾客与卖水的拾荒者决定水类购销节奏。

### 原文关键句
> 「最终预算 = B + R(B × 好评加成) + R(B × 供应商加成) + R(B × 吸引力加成)」
> 「10% 档使用游戏的浮点近似系数，半整数附近可能有 1 点差异。」

## 市场事件一览（market-events）
- URL: https://probably-stolen.nicokobo.com/zh/wiki/terms/market-events

### 机制要点
- 生成判定门槛：**内部天数 D ≤ 5 且未跳过开场**时，不进入随机生成判定。
- 进入判定后，按当前**非装饰性**活跃事件数决定是否新增 1 个普通事件：0 个 → **50%**；1 个 → **35%**；2 个 → **25%**；3 个及以上 → **不再生成**。
- 通过概率判定后**固定生成 1 个**普通事件；冷却与其它筛选会影响可用范围。
- 表中权重是**相对抽取份额**，不是每天概率：15 项总权重 **180**。
- 权重 15 的单次份额 = 15 ÷ 180 ≈ **8.33%**；在无活跃事件（50% 判定）时，该次判定概率 ≈ **4.17%**。
- 活跃事件总数**不足 2 条**时，系统尝试补入**装饰性新闻**（不是固定补足两条花边）。
- 「持续天数」是该工厂默认值，特殊调用可传其它天数。
- **冷却在事件移出活跃列表时登记**，随后按日递减，归零前同一随机入口不能再抽中同一事件；冷却 ≠ 从开始算的固定重现周期。
- 「交易修正」是**品类修正项**，实际报价还要叠商品状态、其它修正与议价，不保证成交价。
- 多数事件有附加**来客动作**，部分在激活时执行专门动作；持续 2 天**不表示**保证出现 2 名顾客。
- 两个事件有定义但**未注册进当前普通随机池**：营养果丰收（3 天/3 天/食物 −20%）、流星雨（3 天/3 天/材料 +50%）。

## 鉴定技巧（appraisal-tips）
- URL: https://probably-stolen.nicokobo.com/zh/wiki/terms/appraisal-tips

### 机制要点
- 鉴定服务的语义是**你给顾客估价**，不是寄给公会代定价；由鉴定委员会成员邀请入会，顾客带来标「待鉴定物品」的货。
- 流程：按检查项算出真实**鉴定基础价值 V** → 提交整数估价 **E**。
- 判定：V 乘各档百分比并**截去小数**得到分界线 T(x)；E 必须落在 **50%–150%** 分界线之间（含两端），否则顾客提出异议。
- 完美档：**T(95) ≤ E ≤ T(105)**，奖金比例 **15%**。
- 极佳档：以 **T(90)** 为下界，奖金比例 **12%**（由算例 E=106 → 12.72 截去小数 = 12 反推）。
- 服务费 = **20 信用点基础费 + int(E × 本档奖金比例)**；奖金用 **E**，不用真实价值 V。
- 收入算例（V=100）：E=100 → 奖金 15、总收入 **35**；E=105 → 15（15.75 截去）→ **35**；E=106 → 12（12.72 截去）→ **32**；E=150 → 7（7.5 截去）→ **27**。
- **估价抬高后掉档，收入反而可能下降**（35 → 32 → 27）。
- 整数边界要单独判断：V=30 时完美估价是 **28–31**。
- 「105% 技巧」：每次估 105% 可多拿 **0–11** 信用点。可多估的值 = `x // 10 // 2`（真实价值舍去个位再除以 2 向下取整）。
- 例：V=45 → 估 45 奖金 int(45×0.15)=6；估 47 → 奖金 int(47×0.15)=7，多 1 点。
- 例：V=255 → 舍去个位 25 → ÷2 = 12（可多估 12），多估收益 2 信用点。
- 入会费：普通模式 **85** 信用点，困难模式 **170** 信用点；在**接受邀请时**扣除，与每次服务费分开。
- Demo 收费实现使用**固定 20** 基础费，未见证书加价分支；不把后续证书收益当作已开放数值。

### 表格 / 数值
| 档位 | E 的区间 | 奖金比例 |
|---|---|---:|
| 完美 | T(95) ≤ E ≤ T(105) | 15% |
| 极佳 | T(90) ≤ E < T(95)（下界明确） | 12% |
| 可接受下限 | E ≥ T(50) | — |
| 可接受上限 | E ≤ T(150) | — |
| 超出 50%–150% | — | 顾客异议 |

| V | E | 奖金 | 总收入 |
|---:|---:|---:|---:|
| 100 | 100 | 15 | 35 |
| 100 | 105 | 15 | 35 |
| 100 | 106 | 12 | 32 |
| 100 | 150 | 7 | 27 |
| 30 | 28–31 | — | 完美档 |

| 项目 | 数值 |
|---|---:|
| 基础服务费 | 20 |
| 完美档奖金 | 15% |
| 极佳档奖金 | 12% |
| 可多估上限算法 | x // 10 // 2 |
| 入会费（普通/困难） | 85 / 170 |

### 触发与前置
- 顾客需带「待鉴定物品」；玩家需已入会（付入会费）。
- 提交前必须先算出 V；不同品类（燃料匣 / 机械手 / 肋明治 / 食品券 / 免疫宁 / 海明威香烟）检查项不同。
- 肋明治命中固定 **40** 的条件后停止加收藏分。

### 后果与风险
- 追求更高估价掉档 → 收入从 35 掉到 32 甚至 27。
- 连续试价 = 消耗顾客耐心，不能当免费探针。
- 把议价后的零售标价当答案 → 整单判错。

### 与其他机制的关联
- 物品鉴定（检查项）；对质（货物异常）；顾客预算（顾客能否付服务费）；议价。

### 原文关键句
> 「服务费先给 20 信用点基础费，再按『提交估价 E × 本档奖金比例』计算奖金并截去小数。奖金使用 E，不使用真实价值 V。」
> 「将物品真实价值的个位舍去，剩下的数值除以 2 后向下取整，就是可以多估的价（x//10//2）。」

## 经营技巧（shop-strategies）
- URL: https://probably-stolen.nicokobo.com/zh/wiki/terms/shop-strategies

### 机制要点
- 现金优先级：先扣「下次账单前」的租金、还款、服务费，再定进货预算。
- **高标价库存不能替代当期付款**：卖不掉 = 现金没回笼。
- 进货前先确认销路：目标顾客的需求 + 预算 + 陈列配合；「基础价值高」不等于「当前客源买得起」。
- 每日核对三件事：成交、夜间生产、服务结算；并留意新闻导致的品类价格变化。
- 排障顺序：先修「原料短缺 / 供电 / 找不到买家」，再添设备。
- 「每天只记四笔账」：①已成交收入（按实际到账）②进货与原料（区分已用掉 vs 仍在库存）③持续支出（租金/还款/服务/能源，分别记）④非正常损失（扣押/失窃/损坏 + 实际赔款）。
- 扩张前三个问题：原料能否持续补上？目标买家真的会买？新增设备/服务会不会挤占账单资金？
- 若问题出在**销路**，加机器只会让库存继续积压。

### 表格 / 数值
| 记账项 | 记录方式 |
|---|---|
| 已成交收入 | 按实际到账 |
| 进货与原料 | 已用掉 / 仍在库存分开 |
| 持续支出 | 租金、还款、服务、能源分别记 |
| 非正常损失 | 扣押、失窃、损坏与实际赔款分开 |

### 触发与前置
- 本页为整合建议，无数值阈值；判断依据是现金/账单日/销路三项。

### 后果与风险
- 用「货物价值增加」当「现金回笼」→ 账单到期缺钱。
- 销路未验证就扩产 → 库存积压 + 账单资金被挤占。

### 与其他机制的关联
- 每日流程（早晨核对）；租金与借款；市场事件（品类价格）；生产。

### 原文关键句
> 「这样更容易区分『货物价值增加』和『现金已经回笼』。卖不掉的成品即使标价很高，也可能导致账单到期时缺钱。」
> 「若问题出在销路，增加机器通常只会让库存继续积压。」

## 常见问题（common-questions）
- URL: https://probably-stolen.nicokobo.com/zh/wiki/terms/common-questions

### 机制要点
- 「价格和图鉴不一样」= 正常：图鉴基础价值**不是保证成交价**；需分别判断物品状态、品质、隐藏特征、真伪、议价、市场事件；**成瘾也可能带来交易惩罚**。
- 机器不产出的四步排查：①是否已睡觉进入下一天、夜间日志有无停电/异常 ②供能方式与实际电源（买了机器≠自动通电）③原料是否放进**机器内部**而非旁边 ④设备状态、当前工序、可用空间（机器模组不是所有生产的必需品）。

|---|---|---|
| 成交价 ≠ 图鉴价 | 状态/品质/隐藏特征/真伪/议价/事件修正 | 逐项核对 |
| 机器不产出 | 未换日 / 未通电 / 原料未入机 / 工序或空间不足 | 夜间日志 + 电源 |
| 道具无效 | 未放到正确位置或未启用 | 右键菜单 |
| 内容缺失 | 试玩版限制 / 网络升级前置 / Mod | 图鉴游戏 ID 对照 |

### 触发与前置
- 换日是夜间产出的前置；电源是机器运行的前置；位置正确是道具生效的前置。

### 后果与风险
- 把「没换日」当「机器坏了」→ 重复买机器。
- 把成瘾惩罚当定价错误 → 反复调价。

### 与其他机制的关联
- 每日流程；机器运行与供电；物品鉴定；展示柜；警报与保险。

### 原文关键句
> 「图鉴基础价值不是保证成交价。物品状态、品质、隐藏特征、真伪、议价和市场事件都需要分别判断；成瘾也可能带来交易惩罚。」
> 「检查正确原料是否放进机器内部，而不是放在旁边。」

## 对质（confrontation）
- URL: https://probably-stolen.nicokobo.com/zh/wiki/terms/confrontation

### 机制要点
- 对质的前提是**指出真实存在的货物问题**：先按原图确认异常，再选对应项目。
- 三类问题不可混为一谈：**真假 / 损坏 / 无法使用**。
- 普通验货对质针对**具体缺陷**；并非「这件货有问题」就能随便勾任何指控。
- 海明威香烟的检查项：字母印刷、颜色、防伪标、商标、包装盒；需比对色卡与印刷，不能只凭盒子颜色相近判真。
- 食品券的检查项：印刷、商标、防伪标、面值、芯片；**低于 160 信用点本来就没有防伪标**；芯片坏了**可能是真券但不可用**。
- 免疫宁的检查项：指示灯、标签、序列号、瓶体；**过期、空针、召回批次都不能按正常可用药收购**。
- 交涉后必须**重新读报价**；原版对话含「承认并降价」「否认错误指控」以及特殊来客的独立回应。
- 原文**不承诺固定降幅或必定赔偿**。
- 只选已确认的项目；对方拒绝时应重新核对具体部位，而不是把所有选项全勾。
- **降价不会修复**坏芯片、裂开的注射器或撕开的收藏品包装。
- 分类边界：燃料匣/机械手/肋明治的重点是「算对估值」（走鉴定服务）；水质/化学品另用检测工具与交涉入口；针对罪犯敲诈、威胁改造体属于**议价**，不能用商品缺陷代替身份判断。

### 表格 / 数值
| 品类 | 检查项 | 易误判点 |
|---|---|---|
| 海明威香烟 | 字母印刷、颜色、防伪标、商标、包装盒 | 只比盒子颜色 |
| 食品券 | 印刷、商标、防伪标、面值、芯片 | **<160 信用点无防伪标**；芯片坏也可能是真券但不可用 |
| 免疫宁注射器 | 指示灯、标签、序列号、瓶体 | 过期/空针/召回批次不能当正常药收购 |
| 肋明治 | 包装、日期、工厂、标志 | 命中固定 **40** 后停止加收藏分 |
| 燃料匣 / 机械手 | 按原图逐项计算 | 走估值而非对质 |

### 触发与前置
- 需先打开物品检查界面并确认异常，才能选对质项。
- 敲诈需对方为**罪犯**；威胁需对方为**改造体**。

### 后果与风险
- 全勾选项 → 错误指控被否认，交涉失败。
- 把「有瑕疵」当「能压价到任意低」→ 降价不修复损坏。
- 用真假推身份 → 敲诈/威胁必定失败并掉声望。

### 与其他机制的关联
- 物品鉴定（检查规则）；买卖与议价（敲诈/威胁）；鉴定技巧（估值 vs 对质）。

### 原文关键句
> 「普通验货对质针对具体缺陷：并非只要这件货有某个问题，随便勾选任何指控都正确。」
> 「降价也不会修复坏芯片、裂开的注射器或撕开的收藏品包装。」

## 展示柜（showcase）— 下钻第 1 层
- URL: https://probably-stolen.nicokobo.com/zh/wiki/terms/showcase
- 下钻来源：daily-cycle / customer-budgets / trading-and-bargaining 三页均链向此页；只取与「交易循环 / 客源 / 预算」直接相关的部分。
- 卡片归属（2026-10-24 去重）：名额、品类价值与来客档位、脏乱扣吸引力、以及「开门时结算 / 吸引力 <100 无买家 / 新档第 1 天不安排」全部交由 wiki-risk 成卡（`showcase-buyer-slots`、`showcase-client-tier`、`attractiveness-dirt-penalty`、`showcase-same-day-rule`，数值同源），本批**不造展柜卡**；本节仅作原始摘要留存。
- 本条为跨规则推论，非 wiki 原文：脏乱扣吸引力与「吸引力 <100 无买家」两条叠加后的结果是「脏乱扣完若跌破 100，当天无展示柜买家」（推断）。wiki 只分别写了这两条规则。

### 机制要点
- 展示柜在**卷帘门左侧**；每天**开门时**按店铺当时状态安排客源；**开门后才加入的展示物要到次日生效**。
- 先布置再开「客源界面（Clientele）」；要区分「陈列带来的预计买家」与「预计普通顾客」。
- 普通可售商品 → 吸引**想买**该类商品的买家；霓虹灯牌（水/食品/医疗/材料）→ 吸引**想卖**该品类的卖家。
- 基础展示柜 = 每天吸引 **1 位**相应买家；展柜 I、II 扩建增加空间与名额。
- 名额算法：从 **1** 起算，满足一项 **+1**：正在使用买家介绍、已解锁展柜 I、已解锁展柜 II，**最多 4 个**；**门面遭破坏时直接回到 1**，加成不算。
- 品类价值 = 该品类**展品价值之和**；统计只覆盖 **11 类主类型**（食品、医疗、材料、日用品、管制药物、武器、护甲、工具、模组、弹药、水）；多标签物品**分别计入各自品类**，带水配给标签的还额外计入水。
- 排序：品类价值**降序**，取前 N（N=名额数），**只保留价值 > 0** 的品类，每个入选项生成一位买家；价值相同按**陈列顺序**，不是随机。
- 来客档位判定顺序：①内部日计数 ≥ **14** 且品类价值 ≥ **350**（日用品 **300**）→ 高价档；②未进高价档且「品类价值 ≥ **145**」或「店铺当前吸引力 ≥ **400**」→ 中价档；③否则默认档。
- 水类特殊分支：柜内**最常见的水类型**会影响实际来客（最常见为纯水时直接是囤水者）。
- 脏乱惩罚：脏乱等级 **≤ 2 不扣**；**> 2** 后从吸引力中减去「**基础吸引力的每级 5%**」（截去小数），再叠加投影设备加成。
- **当日吸引力 < 100 时不会有展示柜买家**；非跳过开场的**第 1 天**也不安排。
- **不要把违禁品放进展示柜**：会招致逮捕；检查对话有「看见展示柜内可疑物品后进行全面检查」分支；展示柜**不具备暗格**的藏匿作用。
- 拾荒者信物：每枚放入都提高到访几率，但**概率不写死**；暗灯响应几率受**黑市声望**影响。

### 表格 / 数值
| 项 | 数值 |
|---|---:|
| 基础展示柜买家 | 1 位/天 |
| 名额基础值 | 1 |
| 每项加成 | +1（买家介绍 / 展柜 I / 展柜 II） |
| 名额上限 | 4 |
| 门面遭破坏 | 回到 1 |
| 高价档：内部日 | ≥ 14 |
| 高价档：品类价值 | ≥ 350（日用品 300） |
| 中价档：品类价值 / 吸引力 | ≥ 145 或 ≥ 400 |
| 脏乱免罚上限 | ≤ 2 |
| 脏乱惩罚 | 每级 −5% 基础吸引力（截去小数） |
| 展示柜买家门槛 | 当日吸引力 ≥ 100 |

### 触发与前置
- 陈列在**开门时**结算，开门后加入次日生效。
- 名额受门面状态影响（被破坏归 1）。
- 吸引力受脏乱与投影设备影响。

### 后果与风险
- 开门后才摆货 → 当天白摆。
- 同品类重复堆 → 只提高该品类排序竞争力，**不是每件各加一位买家**。
- 违禁品入柜 → 招致逮捕 + 全面检查。
- 只堆展示物不顾清洁 → 吸引力跌破 100 后无买家。

### 与其他机制的关联
- 顾客预算（吸引力档位、品类价值）；清洁服务；门面破坏；黑市声望（暗灯）；鉴定证书（招揽鉴定客）。

### 原文关键句
> 「每天开门时，游戏根据店铺当时的状态安排客源；开门后才加入的展示物，要到次日才生效。」
> 「当日吸引力低于 100 时不会有展示柜买家。」
